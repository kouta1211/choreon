# キャンバス（ステージ上の操作）

- 置き場所: `src/features/canvas/` / `src/components/organisms/CanvasBoard.tsx`
- 触れる場所: エディタの中央。作品を開くとすぐ見えるステージ

## 何ができるか

ステージの上に人を置き、掴んで動かし、向きを変え、次のシーンへの導線に
曲線を付ける。シーンを切り替えると、人は前の位置から次の位置へ**補間して動く**
（瞬間移動させない。誰がどこへ動いたかが読めなくなるため）。

## 決まりごと

**値をここへ書かない。** 定数の名前と置き場所だけを書く。数字を写すと、
コードを直したときにこちらが黙って嘘になる（そして誰も気付かない）。

| 決まりごと | 定数 | なぜ |
| --- | --- | --- |
| 矢印キー1回で動く量 | `NUDGE_STEP_SMALL` | 微調整のため小さく |
| Shift + 矢印キー | `NUDGE_STEP_LARGE` | 大きく動かす |
| 遷移時間の既定 | `DEFAULT_TRANSITION_DURATION_SECONDS` | シーンに指定が無いとき |
| 重ね物のなじみ | `OVERLAY_FADE_IN_SECONDS` | 導線と警告は差し替わる。無いと点滅して見える |
| 「動きを減らす」時の上限 | `REDUCED_MOTION_DURATION_SECONDS` | **0 にしない。動き自体が情報**だから |
| 囲んで選ぶしきい値 | `DRAG_THRESHOLD_PX` | これ未満は「叩いた」＝選択解除 |

置き場所: `src/features/canvas/constants.ts` / `lib/nudgeKey.ts` /
`hooks/useMarqueeSelection.ts`。

**実機の台本（`docs/qa-checklist.html`）には具体的な数字を書く。**
あちらは user が画面を見て○×を即答するためのもので、そのときのコードから
写す。ここと役割が違う。

## 選ぶ

`useUIStore.selectedDancerIds` は**並び**（複数選択がある）。

| 操作 | 結果 |
| --- | --- |
| クリック | その人だけ |
| Shift / Ctrl / ⌘ + クリック | 足す・外す |
| **マウスで**何も無い所をドラッグ | 囲んだ人で置き換える |
| Shift + 囲む | 今の選択へ**足す** |
| Alt + 囲む | 囲んだ人を選択から**外す** |
| **指で**何も無い所をドラッグ | シーンを送る（囲まない） |
| Ctrl / ⌘ + A | いまのシーンに立っている全員 |
| 何も無い所を叩く / Esc | 解除 |

**「全員を選ぶ」は、いまのシーンに立っている人だけ**（`lib/selection.ts` の
`dancerIdsInScene`）。ダンサーは作品に属し、立ち位置はシーンに属するので、
そのシーンに立ち位置を持たない人が居うる。混ぜると、整列も向きも効かないのに
選ばれている人ができて「揃えたのに1人ずれている」ように見える。
入口は2つ（右クリックのメニューと Ctrl/⌘+A）だが、絞り込みは同じ関数を通す。

混ぜ方は `useMarqueeSelection` の `marqueeMode()` が修飾キーから決める。
**Alt が優先**（足しながら外すことはできないので、後から足した意図を通す）。
**修飾キーを押したまま空振りで叩いても選択は消さない** — 足す / 外すつもりで
押していただけなので、全部消えると取り返しが面倒。

**マウスと指で意味を変えている**のがここの肝。同じ「何も無い所のドラッグ」を
「囲む」と「シーンを送る」が取り合うので、`event.pointerType` で分けた。
囲むのはマウスの作法（Finder も Figma もそう）で、指で囲むと誤爆する。
PC でシーンを送る道は ← → キー・下の帯・ドックに残してある。

1人のときだけ出すもの（インスペクター・回転ハンドル・曲線の編集）は
`selectPrimaryDancerId(state)` を読む。

**複数のときは何も出さない。** 以前は「◯人を選んでいます」の帯を出していたが、
**ステージに被って邪魔だった**ので外した（2026-08-18、実機の報告 18-1）。
選べていることは丸のリングと、右の一覧の印で分かる。外すのは Esc か、
ステージの何も無い所を叩く。

## 右クリックのメニュー（PC の入口）

人の上で右クリック（指なら長押し）すると、**向きの升**と**削除**が出る。
何も無い所なら「全員を選ぶ / 人を足す」。
`src/components/organisms/StageContextMenu.tsx`。

**なぜ要るか**: 回転のつまみは**1人選んでいるときしか出ない**。
まとめて選んだ何人かを一斉に同じ向きへ揃える道が無かった。

- メニューは**ステージ全体で1つ**。押された場所から DOM を遡って
  「誰の上か」を決める（`lib/contextMenuTarget.ts` の
  `resolveContextMenuTarget`）。1人ずつ持たせない
- **選んでいない人を右クリックしたら、その人だけに選び直す。**
  既に選ばれている人なら選択はそのまま（まとめて当てるため）
- **何人か選んでいるなら、地の上で押しても「選んでいる人たちへの」メニュー**
  （実機の報告 17-21）。丸を狙い直さなくてもまとめた操作へ届く。
  地のメニューが要るときは、何も選んでいない状態で押す
- ボタン・リンク・入力欄の上では開かない。**ステージの下のボタン列は
  DOM の上ではステージ面の中に居る**（枠のすぐ下へ絶対配置している）ので、
  ここで降りないと地のメニューが出る
- 向きは履歴に乗る（`kind: "rotate"`）。**削除は戻せない**
  （`DancerInspector` と同じ方針）

### 整列（2人以上選んでいるとき）

横一列に揃える / 縦一列に揃える / 左右に等間隔 / 前後に等間隔。
計算は `lib/alignment.ts`。

- **揃え先は重心**（`alignmentTarget`）。誰か1人を基準にすると、どれが
  基準になったのか画面から読めない。重心なら動く量の合計がいちばん小さい
- **等間隔は両端を動かさない**（`evenlyDistributed`）。端まで動かすと、
  揃えたつもりが隊形の幅ごと変わる。幅は既に user が決めたものとして扱う
- **格子へ丸めない。** 丸めると等間隔が等間隔でなくなる。揃えると言われて
  半マス動かされるより、頼まれた通りの位置に置く
- 等間隔は**3人以上でないと項目を出さない**（2人では配る余地が無い）
- この2つは**上下の鏡と無関係**。反転は `H - y` の一次変換なので、
  平均も等間隔も写す前後で同じ所へ来る（向きの升とはそこが違う）

### 向きの升（3×3）

刻みは回転のつまみと同じ（`ROTATION_SNAP_STEP_DEGREES`）。
**升の位置は画面の向き、保存するのはステージの向き**で、その写しは
`lib/facing.ts` の `toStageFacing`。札は写した後のステージの意味から引くので、
「客席を上にする」を入れると**「客席を向く」の升が上へ移る**。

ここは囲んで選ぶのと同じ壊れ方（左右は合っているのに前後だけ逆）をする。
**札だけを見ても写し忘れは見つからない**（札も同じ関数から引くため）ので、
テストは升がどの行に描かれるかまで見ている。

## まとめて動かす

**はみ出しは移動量の側で丸める**（`lib/dragMath.ts` の `boundedGroupDelta`）。
1人ずつ端で止めると、壁に当たった人だけ止まって**隊形が潰れる**。
全員が収まる所まで移動量を縮めれば、形を保ったまま端で止まる。
ここが一番壊しやすい。**だから `lib/groupMove.ts` の `groupMoveChanges` に
切り出してある** — DOM もストアも混ぜていないので、壁際の挙動を単体で試せる
（掴んで動かすのを再現しなくても、潰れたら落ちる）。

吸着も**掴んだ本人の位置**で決めて、その差分を全員へ配る。各自で丸めると、
揃えて置いた間隔が崩れる。

**掴んでいる間も、選択中の全員が一緒に動く**（`useGroupDrag`）。移動量は
MotionValue で配るので、動かしてもステージは描き直らない。

**導線も掴んでいる間から動く**（`PathOverlay` の `movingDancerIds`）。
線はストアの座標から引いているが、掴んでいる間ストアは動かないので、
丸と同じ MotionValue を読んで**始点だけ**属性を直に書き換える（終点は
次のシーンの位置なので動かさない）。**離したら必ず書き戻す** — 取り消した
ときは React 側の値が変わらず、書き換えたままの線が残るため。
直線か曲線かは**タグ名**で見る（`SVGLineElement` のような構築子は
環境によって無い。jsdom がそう）。

**丸めは掴んでいる間から効く**（`lib/groupBoundsModifier.ts`）。以前は離した
瞬間にしか効いておらず、誰かが壁に着いたあとも掴んだ本人だけ進んで、
**離すと全員が戻った**（指には「追ってこなかった」ように見える）。
modifier の並びは **格子スナップ → 全員の丸め**。確定側（`handleDragEnd`）も
同じ順で計算しているので、見えている位置と置かれる位置が一致する。

**選択の付け替えは「掴んだ瞬間」にやる**（`handleDragStart`）。離した瞬間に
やっていた頃は、追随の判定（その人が選ばれているか）と確定の判定（掴んだ人が
選択に入っているか）が**違う物を見ていて**、選択の外を掴むと他の人が
動いて見えてから元へ戻った（実機の報告 2026-08-19）。

**移動アニメの最中でも掴める。** 掴んだ瞬間に移動を打ち切って、そのシーンの
位置へ合わせる（`useDancerMotion`）。飛ばさないと、見た目の始点（途中）と
保存の始点（シーンの位置）がずれて、置いた場所と保存される場所が食い違う。
以前は掴ませない印（`isTransitioning`）で避けていたが、**区間の秒数まるごと**
立つ印だったので、8秒の区間では8秒間掴めなかった。

## 導線の曲線の自動補間

**まっすぐ／左右対称の近くまで来たら、ぴったりに寄せる**（`lib/curveSnap.ts`）。
格子への吸着・向きの8方位と同じ考え方 — 指先で「ちょうど」は出せないのに、
目では崩れているのがはっきり分かる（実機の報告 2026-08-19）。

- **まっすぐ** … 制御点が両端の中点に来ると、二次ベジェは直線になる。
  曲げるのをやめたいときの帰り道
- **左右対称** … 中点から線に直交する向きへ出た所。膨らみの量はそのままに、
  傾きだけ正す
- **まっすぐが先。** 中点の近くは直交する線の上でもあるので、順を逆にすると
  「まっすぐにしたいのに、わずかに膨らんだまま止まる」
- しきい値は `CURVE_SNAP_TOLERANCE_UNITS`。格子より広い —
  あちらは線が何本も走っているが、こちらは寄せ先が**点1つと線1本**しか無い
- **格子への吸着の設定には縛られない**（向きの8方位と同じ。格子の話ではない）
- 吸着中はハンドルが光る。効いているかは指先では分からない

## 重なって置けなくなるのを防ぐ

**掴み分けられないほど近く置こうとしたら、置く前に一度聞く**（`lib/overlap.ts`）。
当たり判定は前面の要素で決まるので、丸が重なると**下に居る人へはクリックも
ドラッグも届かない**。一度そうなると、消すかまとめて動かすしか逃げ道が無い
（実機の報告 17-27）。

- 判定は**距離**で見る。しきい値は `OVERLAP_DISTANCE_PX`
  （`canvas/constants.ts`）。「同じ座標か」では、吸着を切っているときに
  見た目は重なったまますり抜ける
- **しきい値は px で持つ。** 掴めるかどうかは丸の大きさ（`MARKER_SIZE`）で
  決まる話で、ステージが何ユニットあるかとは関係が無い。ユニットで
  持っていた頃は、広いステージほど画面上のずれが大きくなっていた
  （実機の報告 17-5）。使うときにステージの実寸から換算する
- 見るのは**動かした人だけ**。もともと重なっていた組にまで文句を言うと、
  触っていない所で止められる
- 聞いている間は**置いた場所に留める**。跳ね返してから板を出すと、
  何を聞かれているのか分からない。保存も履歴も、答えてから
- **ずらす向きは右から時計回りに固定**。毎回違う所へ逃げると、置き直しても
  直感が働かない。8方向どこも埋まっていたら、その人はそのまま置く
- 確認の板は「戻せる操作の念押し」なので `tone: "caution"`。削除と同じ
  ゴミ箱と「元に戻せません」を出すと、戻せるものまで怖く見える

## 上下がひっくり返る

立ち位置は**客席から見た向き**で持っている。設定の「客席を上にする」を
オンにすると、画面では上下が入れ替わって描かれる（`lib/stageFlip.ts` の
`toScreenY`）。**画面の座標を扱うコードは、比べる前に必ずここを通す。**
忘れると、その設定を使っている人にだけ「囲んだのと違う人が選ばれる」
という壊れ方をする。

## 気を付けること

- **`EMPTY_POSITIONS` を `?? {}` に戻さない。** セレクタの中で毎回新しい
  オブジェクトを返すと Zustand が変化と誤検知して無限に再レンダーする
- 枠（囲んで選ぶ矩形）は **state に入れず DOM の style を直接書き換える**。
  state に置くと動かすたびにステージ全部が描き直る
- 編集の確定は `features/scene/hooks/usePositionCommit` を通す。
  自前で保存して自前で履歴に積まない
- **「立ち位置 → `changes[]`」は `lib/` に置く。** コンポーネントの中で
  組み立てると、板ごと描かないと確かめられなくなる。いまある口は
  `groupMoveChanges` / `facingChanges` / `alignmentChanges` の3つで、
  どれも「動かない人は入れない」（何も変わらない1手を履歴に積まない）
