# 曲への載せ方と、曲の区切り

- 置き場所: `src/features/music/` / `src/components/organisms/MusicSheet.tsx` /
  `src/components/organisms/MusicTimeline.tsx`
- 触れる場所: エディタ下の時間軸と、そこから開く「曲」の板

## 何ができるか

振付は**カウントで組み、あとから曲へ載せる**。載せるとは、拍の列を曲の
どこから・どれだけの長さで置くかを決めること。**拍は1つも動かない**ので、
何度載せ直しても振付の中身（何カウント目にどの隊形か）は変わらない。

ショーケースは1本の中で曲が変わる。そのときも**拍の列は切れない**。
切れるのは載せ方の側だけで、これを「区切り」と呼ぶ。区切りごとに
「どの拍から」「曲の何秒目に」「1拍が何秒か」を別々に持てる。

**区切りを置いても隊形は動かない。** 置いた時点では手前と同じ速さ・
同じ秒が入るので、置くこと自体は何も変えない。動かすのはそのあと、
その区間だけ速さや頭を引いたとき。手前の曲には波及しない。

## 決まりごと

**値をここへ書かない。** 定数の名前と置き場所だけを書く。

| 決まりごと | どこ | なぜ |
| --- | --- | --- |
| 拍と秒の写像 | `features/music/lib/placement.ts` | 振付は拍が正。秒は毎回ここから導く |
| 速さの上限・下限 | `MIN_BPM` / `MAX_BPM`（`lib/metronomePreference.ts`） | 1拍が0秒になると全シーンの秒が潰れる |
| 区切りの名前の長さ | `MAX_SECTION_LABEL_LENGTH` | jsonb の1行が青天井に育つのを止める |
| 数える単位 | `BEATS_PER_SET`（`lib/counts.ts`） | 稽古場で数えるのは小節ではなく8カウント |
| 拍線を引く細かさ | `shouldDrawBeatLines` | 潰れて灰色の面になる細かさでは引かない |

区切りを置く位置は、選んでいるシーンから**いちばん近い8カウントの頭**へ
寄せる（曲の変わり目がセットの途中に来ることは、まず無い）。

## 中身

```
placements（保存されるのはこれだけ）
  [{ fromBeat, atSeconds, secondsPerBeat, label? }, ...]
        ↓ secondsAtBeat / withDerivedTimes
  シーンの timeSeconds（メモリ上だけ。保存はしない）
```

| 何をするか | 関数 |
| --- | --- |
| 区切りを増やす | `splitAt`（**秒は1つも動かない**） |
| 区切りを外す | `mergeAt`（後ろが手前の式に吸収される） |
| その区間の速さ | `restretchAt` / `stretchSectionToEnd` |
| その区間の頭 | `moveSectionTo` |
| 画面へ出す一覧 | `sections` |
| その拍・その秒の速さ | `bpmAt` / `bpmAtSeconds` |
| 見えている範囲を区間ごとに割る | `features/music/lib/beatWindows.ts` |
| カウントの見せ方 | `features/music/lib/countLabel.ts` |

画面の側は、時間軸が区間ごとにバーを1本ずつ出し（`TimelineSpanLayer`）、
板の側が一覧を出す（`MusicSectionList`）。どちらも `sections` を読む。

### バーを引かずに押すと、その曲の頭へ縦線が飛ぶ（2026-09-25）

1本の音源に何曲も入っているとき、決めるのは「2曲目が音源の何秒目か」
（`moveSectionTo`）。**引いて決めたあと、そこが本当に2曲目の頭かを
確かめる手立てが無かった** — 頭から流して待つしかない。

- **押すのは本体だけ。** 取っ手（終わりを合わせる側）には乗せない
- **鳴らさない。** 縦線を移すところまでで、再生は
  「いま縦線が立っている所から」始まる約束に任せる
  （`usePlaybackToggle`・user の指示 2026-08-22）。
  独立した試し聴きを作ると、予備拍と「止めた所から続ける」が二重になる
- 押したか引いたかの境目は `isTap`（`features/music/lib/bandTapTarget.ts`）。
  **帯のシークと同じものを読む** — 別々に持つと、同じ手つきで
  帯と区間バーが違う判断をする

⚠️ **厳密な 0 で見ない。** 以前は `moved === 0` だったので、指が1px
動いたタップが**微小な移動として保存されていた**（`atSeconds` が数十
ミリ秒動き、通信も飛ぶ）。しきい値の名前と置き場所は上のとおりで、
**数字はここへ写さない**。

### カウントは曲ごとに数え直す

稽古場では曲が変わったら「2曲目の1」から数える。通しで数えると5分の
作品が `68-3` になり、**誰も口に出さない数**になる。

| 出す所 | 形 | なぜ |
| --- | --- | --- |
| 読む札（一覧・道順・時計） | `2曲目 3-5` | どの曲の 3-5 かが分からないと困る |
| 打ち込む欄 | `3-5` | **出す形と受ける形を揃える**。曲名まで打たされて見えない |
| 区切りが1つの作品 | `3-5` | 区別する相手が居ない（今までどおり） |

読む口は `countLabelAtBeat`、打ち込みは `bareCountLabelAtBeat` と
`beatFromCountLabel`。時間軸のセット番号も同じ数え方で、**区切りの所に
縞の段差が出る**（曲が変わった印なので、出るのが正しい）。

`counts.ts` は**載せ方を知らない**（拍と8カウントの間だけ）。繋ぐのは
`countLabel.ts` 1箇所で、`placements` は**必須の引数**にしてある —
渡し忘れると型で落ちる。文章で「全部直す」と書いても必ず取り残すため。

## 気を付けること

**区間どうしを越境させない。** ある区間の最後の拍が次の区切りの秒を
追い越すと、拍に対する秒が**そこで逆走する**。シーンは `sortScenes` が
`timeSeconds` で並べているので、**隊形の並びそのものが入れ替わる** —
画面は普通に動いて見えるのに、振付が別物になる。だから警告では済まず、
速さの側が頭打ちになる形で止めてある（`maxSecondsPerBeatAt`）。

**次の区切りの `atSeconds` を、手前の操作で動かさない。** あれは
「次の曲が鳴り始める秒」＝曲の側の事実。手前の速さをいじって動くと、
直した覚えの無い2曲目が音からずれる。

**速さを1つだと思わない。** `projects.bpm` の列は残っているが、曲が
変わる作品では区間ごとに違う。メトロノーム・拍線・予備拍は
`bpmAt` / `bpmAtSeconds`（`useActiveBpm`）から読む。

**カウントを出す所は、作る側と見る側の両方を数える。** 2026-08-19 に
作る側の3箇所を数えて、**閲覧画面の5箇所がまるごと漏れた**前例がある。
`placements` を必須にして型で縛ってあるが、**間違ったものを渡すのは
型では止まらない** — `ViewerSceneList.test.tsx` がその網。

**`splitAt` では丸めない。** 「置くだけでは動かない」という約束が、
割り切れない速さの作品でだけミリ秒の桁で崩れる。人が引いた秒を受ける
`moveSectionTo` は丸める。

## 速さを決める口は、いつでもちょうど1つ

| 状態 | どこで決めるか |
| --- | --- |
| 曲なし・区切り1つ | 曲のシートのスライダー（`MetronomeControls`） |
| **曲あり・区切り1つ** | **曲のシートの `速さ(BPM)` の欄**（2026-09-25 に追加） |
| 区切り2つ以上 | 区切り一覧の区間ごとの欄（上の2つは消える） |

時間軸のバーの取っ手を引く操作も**同じ値**を変える。あれは数字ではなく
長さで決める手つきで、口が増えたわけではない。

**クリックして測る**（`TapTempoButton` / `lib/tapTempo.ts`）も同じ値へ書く。
**置き場は速さの欄と同じ**で、区切りが1つならシートに1つ、2つ以上なら
**各行に1つずつ**（その行の区間へ渡す）。

⚠️ はじめは「どの区間を測ったのか読めない」として、区切りが2つ以上の
ときは**出さなかった**。だが**曲が変わる作品こそ、曲ごとの速さを
測りたい** — いちばん要る場面で使えない作りだった
（user の報告 2026-09-25「でてきません」）。
行の中に置けば、どの区間かは画面から読める。

⚠️ **測る相手は、その板の中で鳴らせなければ意味が無い。** 曲のシートは
画面全体を覆う板（`aria-modal`）なので、開いている間は下のバーの再生
ボタンが押せない。「曲に合わせてクリック」と書いてあるのに**鳴らせなかった**
（user の報告 2026-09-25「いまいち使い方がわかりません」）。
測るボタンの隣へ ▶/⏸ を置いた。**押すとその区間の頭から鳴る** — ただ再生すると縦線の居る所から鳴るので、2曲目の行を押したのに1曲目が
鳴ってしまう。送る先の `<audio>` は SceneDock が持ち、時間軸は畳むと
外れるので、`useUIStore.requestSeek` で頼んで持ち主が動かす。押しているのは**下のバーと同じ
`requestTogglePlay`** で、再生の仕組みは増えていない。

⚠️ **「鳴っているか」は、行ごとに言う。** 作品全体の `isPlaying` を行ごとに
配ると、**どの行のボタンも一斉に「止める」へ変わる**（user の報告
2026-09-25「どちらのボタンも反応してしまう」）。
いま鳴っている行は `sectionIndexAtSeconds` で出す。
**秒そのものを読まず、区間の番号へ畳んでから読む** — 秒を読むと毎フレーム
描き直しになるが、番号は境目をまたいだときしか変わらない。

- その行が鳴っている … 押すと**止まる**（秒は動かさない）
- 別の行・止まっている … 押すと**その区間の頭へ送って**鳴らす

### 測った速さが合っているかは、耳で確かめる

測るボタンの右へ **♩**（`useMetronome`）を置いた。押すと**その区間の
速さでクリックが鳴る**。曲も流したまま重ねれば、ずれていれば聴いている
うちに離れていく。

⚠️ **これは「曲があるときは拍を鳴らさない」の例外。** ふだん重ねないのは
「2つの拍が同時に鳴ると、合わせる先が分からなくなる」ためだが、ここは
**合っているかを確かめるために重ねる**。

- 鳴らすのは**一度に1行だけ**。行ごとにフックは呼べない（配列の中）し、
  2行ぶん重なると、どちらの速さを聴いているのか分からなくなる
- 板を閉じると外れて止まる（`BottomSheet` は閉じると中身を外す）
- 音を持つのは organism。`TapTempoButton` は押されたことを伝えるだけ
- **曲に重ねるぶん、音量を上げる**（`OVER_MUSIC_VOLUME`）。ふだんの音量は
  静かな画面で単独に鳴る前提なので、曲に混ぜると負ける
  （user の報告 2026-09-25「音源に負けている」）。
  ⚠️ **ふだんの音量そのものは上げない** — あちらには予備拍が乗っていて、
  「怖い」と言われて柔らかくした経緯がある。上げるとその直しが黙って戻る

- 波形からの自動推定ではない。半分・2倍を取り違えるし、リズムの薄い曲で
  外す。人が数える方は **user が聞いて数えた速さそのもの**なので必ず当たり、
  **曲を入れていない作品でも、スピーカーから流れている音でも使える**
- 平均ではなく**真ん中の値**を採る。1回打ち損ねると平均は戻らない
- 測り直しのボタンは置かない。`MAX_TAP_GAP_MS`（`MIN_BPM` の1拍）より
  間があけば、その前は自動で捨てる

⚠️ **速さを変えたら、載せ方も保存する**（2026-09-25 に直した）。
時間の物差しの正は `music_placements` で、`projects.bpm` は
**同じことを言うもう1つの口**。`useBpm` が `bpm` 列しか書いていなかった
ので、**開き直すと秒だけ古い速さへ戻って**いた（欄は「90」、コマの間隔は
120 のもの）。保存は**載せ方を先に**書く — 途中で落ちたとき、正である
側が残る方を選ぶ。

## 音源は端末にしかない。名前だけは作品に残る

**音源はサーバーへ上げない**（`musicStorage.ts`・IndexedDB、鍵は `projectId`）。
だから**ブラウザが変われば必ず消える**。一方、曲名は作品の一部として
`projects.music_title` に残る。この2つがずれるので、状態は3つある。

| 端末の音源 | 作品の曲名 | 何と呼ぶか |
| --- | --- | --- |
| ある | — | `ready`（鳴らせる） |
| 無い | ある | `missing`（曲で組んであるが、ここでは鳴らせない） |
| 無い | 無い | `none`（まだ曲を入れていない） |

畳むのは `features/music/lib/trackPresence.ts`。**読むのは曲のシートだけ。**

⚠️ **`hasMusic` と混ぜない。** 再生・波形・区間バー・コマの追加・
メトロノームは、どれも `useMusicStore.objectUrl !== null`（＝**この端末に
音が有るか**）で判じている。あちらを「名前があるか」に変えると、
**鳴らせないのに鳴らせるつもりの画面**になる。

> 2026-09-25 の報告「以前、曲を導入していたが、新しく開くと曲が消えてる」は
> これ。**`missing` を表す物が無かった**ので、曲のシートは `none` と同じ顔で
> 描いていた。ホームのカードは `musicTitle` を読んでいて曲名を出しており、
> **同じ作品について2つの画面が違うことを言っていた**。
