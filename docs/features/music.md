# 曲への載せ方と、曲の区切り

- 置き場所: `src/features/music/` / `src/components/organisms/MusicSheet.tsx` /
  `src/components/organisms/MusicTimeline.tsx`
- 触れる場所: エディタ下の時間軸と、そこから開く「曲」の板

## 何ができるか

振付は**カウントで組み、あとから曲へ載せる**。載せるとは、拍の列を曲の
どこから・どれだけの長さで置くかを決めること。**拍は1つも動かない**ので、
何度載せ直しても振付の中身（何カウント目にどの隊形か）は変わらない。

ショーケースは1本の中で曲が変わる。そのときも**拍の列は切れない**。
切れるのは載せ方の側だけで、これを「区切り」と呼ぶ。区切りごとに
「どの拍から」「曲の何秒目に」「1拍が何秒か」を別々に持てる。

**区切りを置いても隊形は動かない。** 置いた時点では手前と同じ速さ・
同じ秒が入るので、置くこと自体は何も変えない。動かすのはそのあと、
その区間だけ速さや頭を引いたとき。手前の曲には波及しない。

## 決まりごと

**値をここへ書かない。** 定数の名前と置き場所だけを書く。

| 決まりごと | どこ | なぜ |
| --- | --- | --- |
| 拍と秒の写像 | `features/music/lib/placement.ts` | 振付は拍が正。秒は毎回ここから導く |
| 速さの上限・下限 | `MIN_BPM` / `MAX_BPM`（`lib/metronomePreference.ts`） | 1拍が0秒になると全シーンの秒が潰れる |
| 区切りの名前の長さ | `MAX_SECTION_LABEL_LENGTH` | jsonb の1行が青天井に育つのを止める |
| 数える単位 | `BEATS_PER_SET`（`lib/counts.ts`） | 稽古場で数えるのは小節ではなく8カウント |
| 拍線を引く細かさ | `shouldDrawBeatLines` | 潰れて灰色の面になる細かさでは引かない |

区切りを置く位置は、選んでいるシーンから**いちばん近い8カウントの頭**へ
寄せる（曲の変わり目がセットの途中に来ることは、まず無い）。

## 中身

```
placements（保存されるのはこれだけ）
  [{ fromBeat, atSeconds, secondsPerBeat, label? }, ...]
        ↓ secondsAtBeat / withDerivedTimes
  シーンの timeSeconds（メモリ上だけ。保存はしない）
```

| 何をするか | 関数 |
| --- | --- |
| 区切りを増やす | `splitAt`（**秒は1つも動かない**） |
| 区切りを外す | `mergeAt`（後ろが手前の式に吸収される） |
| その区間の速さ | `restretchAt` / `stretchSectionToEnd` |
| その区間の頭 | `moveSectionTo` |
| 画面へ出す一覧 | `sections` |
| その拍・その秒の速さ | `bpmAt` / `bpmAtSeconds` |
| 見えている範囲を区間ごとに割る | `features/music/lib/beatWindows.ts` |
| カウントの見せ方 | `features/music/lib/countLabel.ts` |

画面の側は、時間軸が区間ごとにバーを1本ずつ出し（`TimelineSpanLayer`）、
板の側が一覧を出す（`MusicSectionList`）。どちらも `sections` を読む。

### カウントは曲ごとに数え直す

稽古場では曲が変わったら「2曲目の1」から数える。通しで数えると5分の
作品が `68-3` になり、**誰も口に出さない数**になる。

| 出す所 | 形 | なぜ |
| --- | --- | --- |
| 読む札（一覧・道順・時計） | `2曲目 3-5` | どの曲の 3-5 かが分からないと困る |
| 打ち込む欄 | `3-5` | **出す形と受ける形を揃える**。曲名まで打たされて見えない |
| 区切りが1つの作品 | `3-5` | 区別する相手が居ない（今までどおり） |

読む口は `countLabelAtBeat`、打ち込みは `bareCountLabelAtBeat` と
`beatFromCountLabel`。時間軸のセット番号も同じ数え方で、**区切りの所に
縞の段差が出る**（曲が変わった印なので、出るのが正しい）。

`counts.ts` は**載せ方を知らない**（拍と8カウントの間だけ）。繋ぐのは
`countLabel.ts` 1箇所で、`placements` は**必須の引数**にしてある —
渡し忘れると型で落ちる。文章で「全部直す」と書いても必ず取り残すため。

## 気を付けること

**区間どうしを越境させない。** ある区間の最後の拍が次の区切りの秒を
追い越すと、拍に対する秒が**そこで逆走する**。シーンは `sortScenes` が
`timeSeconds` で並べているので、**隊形の並びそのものが入れ替わる** —
画面は普通に動いて見えるのに、振付が別物になる。だから警告では済まず、
速さの側が頭打ちになる形で止めてある（`maxSecondsPerBeatAt`）。

**次の区切りの `atSeconds` を、手前の操作で動かさない。** あれは
「次の曲が鳴り始める秒」＝曲の側の事実。手前の速さをいじって動くと、
直した覚えの無い2曲目が音からずれる。

**速さを1つだと思わない。** `projects.bpm` の列は残っているが、曲が
変わる作品では区間ごとに違う。メトロノーム・拍線・予備拍は
`bpmAt` / `bpmAtSeconds`（`useActiveBpm`）から読む。

**カウントを出す所は、作る側と見る側の両方を数える。** 2026-08-19 に
作る側の3箇所を数えて、**閲覧画面の5箇所がまるごと漏れた**前例がある。
`placements` を必須にして型で縛ってあるが、**間違ったものを渡すのは
型では止まらない** — `ViewerSceneList.test.tsx` がその網。

**`splitAt` では丸めない。** 「置くだけでは動かない」という約束が、
割り切れない速さの作品でだけミリ秒の桁で崩れる。人が引いた秒を受ける
`moveSectionTo` は丸める。
