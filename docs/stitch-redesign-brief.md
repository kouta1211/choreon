# Choreon 再デザイン依頼書

**このアプリを一度も見たことがない人が、全画面のデザインを担当する**前提で書いています。
Google Stitch に渡すことを想定していますが、人間のデザイナーにそのまま渡しても読める形にしてあります。

読む順番: §1（何のアプリか）→ §2（誰がどこで使うか）→ §3（画面の一覧）→ §4（守ってほしいこと）→ §5（方針）→ §6（Stitch への渡し方）

---

## 1. 何のアプリか

**ダンスの「隊形（フォーメーション）」を作る道具です。**

複数人で踊るとき、曲のどこで誰がどこに立つか、どう移動するかを決めます。これを紙に丸を描いて
矢印で結んだものが「隊形図」で、いまも多くの現場で手書きです。Choreon はそれを画面の上でやり、
**曲の時間に沿って動かして見られる**ようにしたものです。

### 中心にある考え方

```
上から見た長方形のステージに、丸いマーカー（＝ダンサー）を置く
　　　画面の上 ＝ バックステージ（舞台の奥）
　　　画面の下 ＝ 客席側（お客さんがいる方）
　　　※ この向きは絶対に反転しません。振付の現場で共有されている見方です

「シーン」＝ある瞬間の隊形。曲の何秒目か、を持っています
　　　シーンとシーンの間隔が、そのまま移動にかけられる時間になります
　　　例）4秒あいていれば、4秒で次の位置へ歩く
```

### 知らないと読めない言葉（画面に日本語でそのまま出ます）

| 言葉 | 意味 |
|---|---|
| 隊形 / フォーメーション | ある瞬間の全員の立ち位置 |
| シーン | 隊形1つ。曲の何秒目かを持つ |
| 8カウント | 稽古場で数える単位。1・2・3…8 と数えて1セット。**小節ではありません** |
| 上手（かみて）/ 下手（しもて） | **客席から見た**右／左。画面では左が下手 |
| バックステージ | 舞台の奥。画面の上 |
| バミリ | 床に貼る目印。立ち位置の跡 |
| 顔被り（かおかぶり） | 前の人の真後ろに入って、客席から見えない状態 |
| マイ・フォーカス | 1人だけを目立たせて、その人の動きを追う表示 |
| 導線 | あるシーンから次のシーンへ移動する道筋の線 |

## 2. 誰が、どこで、どう使うか

### 利用者は2種類

**A. 振付師（作る人）** — 隊形を組み、直し、共有する。作業時間は長い（1曲に数時間）。
自宅のPCで組み、稽古場のスマホで直す、という往復をします。

**B. ダンサー（見る人）** — 配られたリンクを開いて、**「サビで自分はどこか」**だけを知りたい。
編集は一切しません。滞在時間は数十秒。

### 使われる場所の条件（デザインの前提）

- **稽古場**。鏡張りで、照明は明るかったり暗かったりする。床に置いて上から覗き込むことも多い
- **片手**。もう片方の手には飲み物か、スマホスタンドか、何も持てない状態
- **音楽が鳴っている**。音でのフィードバックは当てにできない
- **急いでいる**。曲が止まっている数十秒のあいだに確認して、また踊る
- **電波が悪い**（地下スタジオが多い）

### この前提から出ている、いまの決まりごと

- 押す的は最低 **44px**、画面の下端から **24px** 以上あける
- **ページ自体をスクロールさせない**。ステージと下の操作列が常に同時に見えている
- ホバーでしか出ない機能を作らない
- 音ではなく**触覚**（バイブ）で返す

## 3. 画面の一覧

全部で **6つのルート**と、**8つのシート**、**2つのダイアログ**があります。

### 3-1. `/` トップ（未ログイン）— いきなり編集画面

アカウントを作る前に、**まず触ってもらう**方針です。「はじめてのフォーメーション」という
サンプル（4人・3シーン）が最初から入っていて、すぐ動かせます。保存しようとした瞬間に
初めて登録を求めます。

→ 画面の中身は 3-4 のエディタと同一。違いは右上に「保存」ボタンが出ることだけ。

### 3-2. `/` トップ（ログイン済み）— 作品の一覧

- ヘッダー: ブランド「Choreon」／テーマ切り替えボタン／ログアウト
- 新規作成フォーム（1行の入力＋丸いボタン）
- 作品カードの縦並び。1枚に **サムネイル（先頭シーンの隊形を点で描いたもの）／作品名／
  「5シーン · 6人 · 7.4秒」／ダンサーの色ドット／削除ボタン**
- 0件のときの空状態あり

### 3-3. `/login` `/signup` — 認証

背景にうっすらステージ（格子を傾けたもの）＋照明のような光。中央にブランドとカード。
「紙のフォーメーション図を、動く絵コンテに。」というコピーが入ります。

### 3-4. `/projects/[id]` — エディタ（このアプリの本体）

**縦3ブロック。ページはスクロールしません。**

```
┌─────────────────────────────────┐
│ ヘッダー 40px                                          │
│  ← 戻る │ 作品名（破線枠＋鉛筆＝編集できる印） │ ♪曲 │ 共有 │ ✨診断 │ +人 │ ≡表示  │
├─────────────────────────────────┤
│                                                        │
│              ステージ（上下中央・flex-1）                  │
│         上＝バックステージ ／ 下＝客席側                    │
│         丸いマーカー ＝ ダンサー（40px・6色・名前つき）      │
│         ドラッグで移動／回転ハンドル／曲線の制御点            │
│         右下に 元に戻す・やり直す                          │
│                                                        │
│   ステージ直下: [テンプレート44px]        「客席側」        │
├─────────────────────────────────┤
│ インスペクター（ダンサーを選んでいる間だけ、ドックの直上に出る）  │
├─────────────────────────────────┤
│ ドック（下端固定・約187px）                               │
│   ─ 持ち手（上スワイプでシーン一覧）                       │
│   ▶ 再生44px │ S3 サビ入り │ 00:12.40 / 03:24 │ +追加      │
│   時間軸の帯 80px … 曲の波形の上に、シーンのコマが時刻の位置に  │
│   ミニマップ 14px … 曲全体と、いま見ている範囲               │
└─────────────────────────────────┘
```

**時間軸の帯がこのアプリで一番の発明です。** 横位置がそのまま曲の時刻で、コマ（隊形の
ミニチュア）が時刻の真上に載っています。コマを横に引くと、その隊形が曲の中で動きます。
コマが詰まってくると「コマ → 番号だけの旗 → 『4シーン』という束ね」と段階的に縮退します。

曲を入れていないときは、波形の代わりに **8カウントごとの縞と拍線**が敷かれます
（「機能が欠けた画面」ではなく「カウントで組む画面」に見せるため）。

**広い画面では横に開きます**（同じ部品のまま、配置だけ変わる）:

| 幅 | 形 |
|---|---|
| 〜767px | 1カラム＋下のドック（上記） |
| 768〜1199px | 左にステージ、右300pxにパネル（シーン／ダンサーのタブ） |
| 1200px〜 | 3ペイン。左268px＝シーン一覧、中央＝ステージ、右300px＝選択中のダンサー＋ダンサー一覧 |

### 3-5. `/view/[id]` — 閲覧専用ビューア（ダンサーが見る画面）

**編集の操作を1つも持ちません。** 共有リンクで開きます。

**入口（最初の1画面）**: 「あなたはどれですか」。1シーン目の立ち位置を絵で出し、
丸か名前チップのどちらからでも自分を選べます。

**本体**:

```
ヘッダー40px  作品名 │ 自分のポジション（押すと選び直し）
ステージ      自分＝塗り36px＋リング＋名前 ／ 他人＝輪郭だけ26px
道順の1行     「→ 下手前へ 約4歩（1.6秒かけて）」    [ぜんぶ]
曲の1行       「同じ曲をこの端末で選ぶ」
スクラブ帯56px  画面幅いっぱい。再生ヘッドは常に中央
目盛り14px
```

**エディタとは階層が逆**です。主役は再生ボタンではなく**スクラブ（指で時間をこする操作）**。
知りたいのは特定の瞬間の立ち位置で、それは指で止められる方が速いからです。
再生ボタンは36pxの枠線ボタンに格下げしています。

「ぜんぶ」を押すと**道順シート**が開き、全シーンぶんの移動が文章で並びます
（「3 下手前へ 約4歩 / 0:12 · 1.6秒かけて」）。

### 3-6. `/offline` — 圏外

一度開いた画面は見られること、戻れば読めることを伝える1画面。

### 3-7. シート（下から出る板）8種

| シート | 中身 |
|---|---|
| シーン一覧 | 全シーンの行。ドラッグで並び替え、複製、削除、時刻の入力 |
| ダンサー追加 | 名前の入力＋**次に割り当てられる色を先に見せる**＋ミニステージの説明 |
| フォーメーション | 人数レール（2〜10人）＋ **59種のテンプレート**＋変形（左右反転・前後反転・90°回転・間隔） |
| 曲 | ファイルを選ぶ／頭出しの秒数／拍子／メトロノーム／BPM |
| 見た目 | **10種のテーマ**＋背景の質感7種。ミニチュアで見比べる |
| 隊形を見てもらう | AIに1シーンを見てもらい、200字程度の所見をもらう |
| 共有 | リンクのオン/オフ、全体リンク、一人ひとりのリンク、作り直し |
| 動画にする | 720p/1080p、名前の表示、進み具合、書き出し |

### 3-8. 重ね物

- **確認ダイアログ** — 削除の前。「一緒に何が消えるか」を数のチップで出す（`6 配置` `1 導線`）
- **トースト** — ドックの直上に出る。1つだけ。横スワイプで消す
- **説明ポップオーバー** — 長押し450ms／`?`／初回の1回で出る
- **チュートリアル** — 初回だけ、本物の要素を指しながら5ステップ

## 4. 守ってほしいこと（デザインを変えても動かせない前提）

1. **上＝バックステージ、下＝客席側。** 反転させない
2. **警告に色を使わない。** ダンサーは6色から選べ、**赤いダンサーが普通にいます**。
   危険や注意は「形（アイコン）＋数値」で伝える。警告の定位置は
   左上＝顔被り／右上＝速すぎる移動／右下＝移動中の衝突
3. **ダンサーの6色は変えられない**（保存されている実データ）:
   `#3b82f6` `#ef4444` `#10b981` `#f59e0b` `#8b5cf6` `#ec4899`
4. **ステージ面に常設のボタンを置かない。** 下にダンサーが来て隠れる
5. **タップ領域44px、下端24px、ページはスクロールさせない**
6. **ホバーだけで到達できる機能を作らない**
7. **日本語のドメイン用語を言い換えない**（§1の表。現場の言葉です）
8. 1マス＝実寸90cm。既定のステージは14×10マス（12.6m×9m）

## 5. デザインの方針（3案と、おすすめ）

いまは「暗い地＋ピンクのアクセント」を既定に、10テーマを切り替えられる作りです。
**再デザインでは、まず既定の1つを強く決めてほしい**というのが依頼の芯です。

### 案A: 稽古場の道具（Tool for the room）★おすすめ

暗い地・低彩度・アクセント1色。情報は**位置と形**で伝え、色は「いま選んでいるもの」だけに使う。
文字は小さくても読める行間で、装飾は影と1pxの線だけ。

- **なぜ**: 実際に使われるのは暗い稽古場で、隣に鏡があり、ダンサーの6色が常に画面にある。
  UIが色を持つほど、ダンサーの色と競合して「誰がどこか」が読みにくくなる
- **危うさ**: 無味乾燥に振れやすい。手触り（押し込み・持ち上げ）で温度を出す必要がある

### 案B: 紙の隊形図（Paper）

クリーム色の紙、赤鉛筆の丸、手書きの矢印。いまも現場で使われている紙の見た目を、
そのままデジタルにする。

- **なぜ**: 移行の抵抗がいちばん小さい。年配の振付師や、紙で覚えた人に「同じもの」に見える
- **危うさ**: 明るい地の上では、6色のダンサーがくすむ。暗所での可読性が落ちる。
  「動く」ことの気持ちよさを紙の比喩が邪魔する

### 案C: 舞台（Stage）

黒い床、スポットの光、板張りの質感。ステージそのものをアプリの中に持ち込む。

- **なぜ**: 一番「気分が上がる」。SNSに貼りたくなる画面になる
- **危うさ**: 光と影が情報の邪魔をする。長時間の編集には疲れる

### おすすめ: **案Aを既定にして、案Bと案Cはテーマとして残す**

理由は3つです。

1. このアプリで一番長く見られるのは**時間軸の帯**で、そこは波形・コマ・拍線・再生ヘッドが
   重なる情報密度の高い場所です。地が静かでないと成立しません
2. ダンサーの6色が常に主役なので、**UIの色は脇役に徹する**必要があります
3. 紙と舞台は「気分」に効きますが、毎日3時間使う人には**静かな方が勝ちます**。
   ただし初見の印象では紙と舞台が強いので、テーマとして選べる価値はあります

**温度の出し方**（案Aを選んだ場合の具体策）: 色ではなく**動き**で出す。押した瞬間の沈み込み、
掴んだときの持ち上がり、シーンが切り替わるときの補間、時間軸を払ったときの慣性。
すでにその土台はあるので、そこを設計の対象にしてください。

## 6. 既存アプリとの差別化（デザインで効かせられる点）

同種のアプリ（海外の Formation 系、マーチングバンド向けの3Dソフト、あるいは紙とホワイトボード）
と比べたときの、Choreon の立ち位置です。

| 差別化の芯 | デザインで効かせる場所 |
|---|---|
| **曲の時間軸に隊形が載っている**（他は「順番」で並ぶだけのものが多い） | 時間軸の帯。ここを画面の主役にする。コマの縮退（コマ→旗→束ね）を美しく見せられれば、それ自体が「このアプリらしさ」になる |
| **稽古場のスマホが主戦場**（他はPC前提が多い） | 片手で届く範囲に操作を集める。下端の重心、44pxの的、暗所での可読性 |
| **ダンサー向けの画面が別にある**（他は振付師しか見ない） | ビューアの「あなたはどれですか」と、道順を**言葉にする**表示。ここは他にほぼ無い。 |
| **紙の隊形図の見た目にもできる** | テーマ。移行のハードルを下げる物語として使える |

**いちばん独自なのは「道順を言葉にする」ところ**だと考えています。
「下手前へ 約4歩（1.6秒かけて）」は、座標を読めない人にも届く形です。
ここをもっと前に出すデザイン（たとえばビューアの主役を絵ではなく言葉にする案）も
検討する価値があります。

## 7. いま課題だと感じている点（デザインで解いてほしい）

実装してきた立場から、正直に挙げます。

1. **エディタのヘッダーにアイコンが6つ並んでいる**（保存・曲・共有・診断・追加・表示メニュー）。
   機能が増えるたびにここへ足してきた結果で、初見では何がどれか分かりません。
   **整理か、別の置き場所の提案がほしい**
2. **ドックが縦を187px使う**。持ち手・操作行・時間軸・ミニマップの4段で、
   狭い端末ではステージが圧迫されます。段を減らせないか
3. **「表示とモード」メニューの中身が雑多**（目盛り3択・導線・顔被り・バミリ・払って送る・
   動画にする・使い方・テーマ上書き）。性質の違うものが1つの引き出しに入っています
4. **警告に色を使えない制約が、形と数値の情報を増やしている**。
   ステージ上のバッジが3種類（顔被り・速すぎ・衝突）あり、密集すると読めません
5. **テーマが10種＋質感7種で多すぎる**。既定以外は検証が薄く、
   「選べること」自体が価値になっていない可能性があります
6. **空状態とエラー状態の設計が薄い**。0件・読み込み中・失敗のときの画面が、
   本編ほど作り込まれていません
7. **エディタとビューアで語彙が違う**（再生ボタンの大きさの階層が逆）。
   意図的な判断ですが、両方を見る振付師には「別のアプリ」に見えるかもしれません

## 8. Google Stitch への渡し方

### 8-1. 最初に貼るプロンプト（この文書の §1〜§4 の要約）

```
ダンスのフォーメーション（隊形）を作るアプリのUIをデザインしてください。

上から見た長方形のステージに、丸いマーカー（ダンサー）を配置します。
画面の上がバックステージ、下が客席側です（反転させないでください）。
画面の下には「曲の時間軸」があり、隊形のミニチュアが曲の時刻の位置に並びます。

主に稽古場のスマートフォンで、片手で、音楽が鳴っている中で使われます。
- タップ領域は最低44px、画面の下端から24px以上あける
- ページ自体はスクロールさせない（ステージと下の操作列が常に見えている）
- ホバーだけで使える機能を作らない
- 警告に色を使わない（ダンサーが6色から選ぶので、赤い人が普通にいる）
  注意は形（アイコン）と数値で伝える

トーン: 暗い地・低彩度・アクセント1色。情報は位置と形で伝え、
色は「いま選んでいるもの」だけに使う。装飾は影と1pxの線まで。
```

そのうえで、画面ごとに1つずつ依頼します（§3 の各項目がそのまま1プロンプトになります）。

### 8-2. 撮って貼るスクリーンショットの一覧

**幅は必ず2種類**（390px＝iPhone / 1440px＝PC）。ブラウザの開発者ツールで幅を指定して撮ります。

| # | 画面 | 状態 | なぜ要るか |
|---|---|---|---|
| 1 | エディタ | 4人・3シーン、曲あり | 全体の骨格。**最優先** |
| 2 | エディタ | 曲なし（8カウントの縞） | 地の違いを見せる |
| 3 | 時間軸の帯 | コマが詰まって旗・束ねになった状態 | 縮退はこのアプリ独自。**言葉で説明しにくい** |
| 4 | エディタ | ダンサーを選択（インスペクターが出た状態） | 選択の語彙 |
| 5 | エディタ | 警告が出た状態（顔被り・速すぎ） | 色を使わない警告の実際 |
| 6 | エディタ | 1440px（3ペイン） | 広い画面の配置 |
| 7 | フォーメーションのシート | 6人・一覧が見える状態 | 59種の見せ方 |
| 8 | 見た目のシート | テーマ一覧のミニチュア | テーマ機構の存在 |
| 9 | ビューア | 入口「あなたはどれですか」 | ダンサー向けの入口 |
| 10 | ビューア | 本体（自分が選ばれた状態） | 塗りと輪郭の描き分け |
| 11 | ビューア | 道順シート | **独自性がいちばん出る画面** |
| 12 | 作品の一覧 | 3件ほど | 入口の印象 |
| 13 | 確認ダイアログ | シーン削除 | 重ね物の語彙 |
| 14 | 紙のテーマ | エディタ | 「同じ画面が別の素材になる」ことの証明 |

貼るときは **1枚ずつ、何の画面かを1行添えて**貼ってください。まとめて貼ると、
Stitch は画面の対応を取り違えます。

### 8-3. Stitch に頼むときのコツ

- **1回に1画面**。「アプリ全体」を頼むと平均化された無難な案が出ます
- **要素の一覧を先に書き、レイアウトは指定しない**。位置を決めるのはこちらの仕事ではなく、
  提案してもらう部分です
- **却下する条件を書く**（例: 「ステージの上にボタンを置かない」）。
  Stitch は空いている場所にボタンを置きたがります
- 出てきた案は**必ず §4 の8項目と照らす**。1つでも破っていたら、その項目を引用して直させる
