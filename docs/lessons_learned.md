## 2026-08-18

- **サーバーの props とストアのずれは「保存できていない」ように見える。**
  設定でステージの数字を変えても画面が変わらなかった（報告 03-17）。
  原因は保存の失敗ではなく、サーバーが渡した props を素直に描いていたこと。
  → 編集で変わるものを描く側は、ストアを優先して読む（`EditorLayout` の `live`）。
  同じ書き方は `ProjectTitle.tsx` `ShareSheet.tsx` に前からあった。
  **1箇所で見つけたら、同じ形が他にもないか探す。**

- **`1fr` は等幅ではない。** 3択のボタンが 48 / 64 / 41px とばらけた。
  `1fr` は `minmax(auto, 1fr)` なので、中身が広い列が勝つ。
  → 等幅にしたいときは `repeat(n, minmax(0, 1fr))`。

- **見た目を借りるために、キーボードで辿れる部品を置き換えない。**
  メニューの中の選択肢を独自ボタンに差し替えたら、Tab でも矢印でも
  辿り着けなくなった（Radix のメニューは中の項目を自前で管理しているため）。
  → 中身は `DropdownMenuRadioItem` のまま、**クラスと見た目だけ借りる**。

- **1回の処理で2つ保存すると、後の1つが前を巻き戻す。**
  レンダー時のクロージャが古い値を掴んでいた。
  → まとめて適用するときは `useProjectStore.getState()` でその場の最新を読む。

- **テストに歯があるか確かめる。** 上のバグのテストを書いたあと、直した側を
  一時的に戻したら期待どおり落ちた（「20 のはずが 15」）。
  これを確かめるまで、テストは書いたことにならない。

- **本番のチャンクを grep して「無い」と判断しない。** 追加した文言が
  見つからず未反映かと思ったが、i18n は遅延読み込みのチャンクに入っていた。
  → **見つかったときだけ信じる**。無いことの証明はブラウザで確かめる。

- **同じ一覧を2つのファイルに書かない。** AI に読ませない指定を
  `.claudeignore` と `.claude/settings.json` の両方へ書いたが、**片方は効かない**。
  効かない方を信じて直す事故が起きる形だった。
  → 一覧は効く側にだけ置き、もう片方は案内文にする。調べた結果は ADR へ
  （`docs/architecture/decisions/0002-...`）。

- **docs に数字を写すと、黙って嘘になる。** 機能ドキュメントにしきい値や
  既定値を書いた直後に、これはコードを直せば古くなると気付いた。
  しかも lint もテストも何も言わない。
  → 定数の**名前と置き場所**を書く。数字が要るのは実機の台本だけ。

- **「品質を守る」はルールではなく仕掛けにする。** 「any 禁止」を規約に書く前に
  測ったら、既に ESLint が error で `src/` の使用箇所は 0 だった。書く必要が
  無かった。逆に `await` の付け忘れは**何も見ていなかった**ので、
  `no-floating-promises` を足した（`src/` の本番コードのみ、約15秒）。
  → 品質のルールを書く前に、**いま何が機械で守られているかを測る**。
  守られているなら書かない、守られていないなら仕掛けを足す。
  規約に書くのは、機械で見られないものだけ。

- **ルールを狭めるとき、「学習中だから」を理由に自分の判断を挟まない。**
  「軽微な修正は説明不要」に対して、基礎の概念が出たときだけ説明する例外を
  残す提案をしたが、user は**外す**を選んだ。
  → 明示された指示を、良かれと思って弱めない。必要なら user が聞く。
  出力の量に関する指示は、そのまま従う。

- **「テストが無い」を、抜けと決めつけない。** `useStageScrubGesture` に
  テストが無いのを見て「手厚い方針なのにここだけ抜けている」と報告したが、
  数えたら **canvas の11フック全部にテストが無かった**。抜けではなく方針
  （`lib/` の純粋関数を厚く書き、フックは書かない）。
  → 1件を見て方針を推測しない。**同じ層を全部数えてから言う。**
  本物の穴は `lib/` の未テスト5件の方だった。

- **検査コマンドは、書いた日に一度は流す。** 保守点検の色検査
  `git grep "zinc-\|pink-\|slate-"` は、`tran`**`slate-`**`x-1/2` に誤爆して
  25件すべて偽陽性だった。角丸の検査も、正規の `rounded-[var(--radius)]` を
  62件数えていた。**どちらも書いたまま一度も流されていなかった。**
  → 手順書に書いたコマンドは、書いた時点で実行して**出力を見る**。
  0件を期待する検査なら、0件になることを確かめる。

- **手順に例があるなら、読まれるのは例の方。注意書きではなく例を直す。**
  `/commit` に「末尾に Co-Authored-By を付ける」と注意書きを置いていたのに、
  自分で例を写して trailer を落とした。**書いてあっても守られない。**
  → 正しい姿を例の中に入れる。注意書きで補うのは、例に入れられないときだけ。

- **後から足すテストは、書いた時点で通る。だから壊して確かめる。**
  `formationChoices` に8件書いて全部通ったが、畳む処理を外したら
  **1件しか落ちなかった**。呼び出し回数と結果の件数が揃うせいで、
  1件が通り抜けていた。締め直して2件落ちるようにした。
  → 実装が既にある所へテストを足すときは、**その関数がやっていること
  ごとに1つずつ壊す**。落ちなかったテストは何も守っていない。

- **コマンドの欠陥は、1回通せば出る。** 14個を作った日には見えず、
  1本（`/branch` → テスト → `/commit` → `/pr`）を通した1回で3つ出た
  （`test/` 接頭辞が無い / trailer を落とす例 / 既存コードへ足す手順が無い）。
  → 手順書は、書いた分だけ良くならない。**通した分だけ良くなる。**

- **無人の実行環境には `.env.local` が無い。** 夜のルーティンを作って試し打ち
  したら、投稿できなかった。**リポジトリを clone して動くので、gitignore
  してあるファイルは存在しない。** しかも Notion の MCP も無人セッションでは
  未認証で、**両方の経路が同時に塞がっていた**。
  → 秘密が要る無人ルーティンは、**鍵を実行環境側の環境変数として登録する**
  必要がある。リポジトリの中を探しても永遠に見つからない。
  なお、失敗の仕方は正しかった（ゴミを投稿せず、原因を報告した）。
  **作った当日に1回走らせたから分かった。** 夜まで待っていたら、
  翌朝「投稿されていない」だけが残っていた。

- **MCP のコネクタが「付いている」ことと、道具が「渡る」ことは別。**
  夜のルーティンに Notion のコネクタを付けたのに投稿できず、最初は
  「使える道具を絞りすぎた自分の設定ミス」だと考えた。広げて2回目を走らせ、
  実行ログの `ToolSearch` を読んだら **GitHub の道具は出るのに Notion は0件**。
  設定ではなく、無人セッションには渡らない仕組みだった。
  → **推測で原因を決めない。ログの中の「何が見えていたか」を読む。**
  1回目の失敗で決めつけていたら、間違った直し方をしていた。

- **まだ困っていない問題を解かない。** 無人での日報投稿に、この日いちばん
  長く時間を使った。結局いまは `/wrap-up` を1語打つ運用に落ち着いている。
  → 自動化は**手でやって面倒だと分かってから**。順番を逆にすると、
  動かない仕組みの調査に1日が溶ける。

- **`git add` を絞っても、`git commit` は索引ぜんぶを取る。**
  自分の3ファイルだけ `add` して `commit` したら、user が先にステージして
  あった作業 1037 行を巻き込んだ（timelag）。`reset --soft` で分け直した。
  → **コミットの前に `git status` で索引の中身を見る。** 迷ったら
  `git commit -F - -- <パス>` と名指しで出す。手順は `/commit` へ書いた
  （これで2回目なので箇条書きではなく手順へ昇格させた）。

- **motion の `style` に `transform` のキーがあると、`x` / `y` は効かない。**
  まとめて動かす実装で、掴んだ本人だけ動いて他が止まったままだった。
  `transform: undefined` でも**キーが在るだけで**負ける。
  → 追従する側は `transform` を**キーごと入れない**形に分ける
  （`DraggableDancerIcon.tsx`）。値を `undefined` にするのでは足りない。

- **高さは親から降りてくる。`h-full` の親を `min-h-dvh` にすると潰れる。**
  閲覧画面をスクロールできるようにした瞬間、ステージが 1×1 になった。
  `min-h-` は高さを確定させないので、子の `h-full` が拾えない。
  → **スクロールさせる親の下で `h-full` を使わない。** その枠に
  `h-[min(140vw,520px)]` のような**確定する高さ**を与える。

- **Tailwind の任意メディアクエリに空白を入れると、CSS が全部落ちる。**
  `[@media(min-width:768px)and(min-height:600px)]` は `and` が関数扱いになり、
  `globals.css` ごと壊れて画面が真っ白になった。しかも**ソースを直しても
  500 が残る**（Turbopack のキャッシュ）。
  → 空白は `_` で書く。**まず既定のブレークポイント（`min-[1024px]:`）で
  済まないかを考える。** 直したのに直らないときは、開発サーバーを立て直す。

- **自分のルール違反に、自分では気づけなかった。** ブラウザの戻る＝元に戻す
  を**テスト無しで出荷**していた。気づいたのは翌日、user に挙動を訊かれて
  実装を読み直したとき。verify は通っていたし、lint も何も言わなかった。
  → **「テストを書いたか」は verify が見ていない。** 機能を出す手順
  （`/commit` の前）で、隣に `.test.` があるかを自分で数える。
  なお、書いた7件は実装を3通り壊して落ちることまで確かめた（`5999919`）。

- **Windows の Python でファイルを書き直すと、行末が LF → CRLF に化ける。**
  `docs/qa-checklist.html` に10項目足しただけなのに、`git diff --stat` が
  **3500行の書き換え**になった。`io.open(p, "w")` はテキストモードなので
  `\n` を `os.linesep`（`\r\n`）で書く。このリポジトリは LF で入っている。
  → **差分の行数を必ず見る。** 足した行数と桁が合わなければ行末を疑う。
  直すのは `s.replace(/\r\n/g, "\n")` で書き戻すだけ。**気づかず出すと、
  次に触る人の差分が毎回全書き換えになる**（レビューが成立しなくなる）。

- **DOM の見た目の位置と、DOM の中の位置は違う。** 右クリックのメニューで
  「ステージの面の上か」を `closest('[data-testid="stage"]')` で見たら、
  ステージの**下**に並んでいるボタン（テンプレート・元に戻す）でも真になった。
  あれは枠のすぐ下へ `absolute` で置いてあるので、**DOM の上では面の中に居る**。
  → 当たり判定は、見えている場所ではなく**DOM を読んで**決める。
  ボタン・リンク・入力欄は先に除外する（囲んで選ぶ側と同じ形にした）。

- **札と升を同じ関数から引くと、写し忘れをテストが見逃す。**
  向きの升は「画面の向き」で並べ、保存は「ステージの向き」へ写す。
  上下の鏡（`toStageFacing`）を外しても、**札もそこから引いているので
  「奥を向く」を押せば 180 が入り**、テストは緑のままだった。
  → **写像を挟むものは、写した結果だけでなく「どこに描かれたか」を見る。**
  升がどの行に出るか（`style.gridRow`）まで見て、初めて落ちるようになった。

- **`prettier --write` にワイルドカードを渡さない。** 切り出しの仕上げに
  `npx prettier --write src/features/canvas/lib/*.ts` と打ったら、**触って
  いない8ファイル**まで整形されて差分に乗った（中身は行の折り返しだけ）。
  コミット直前の `git status` で気づいて `git checkout --` で戻した。
  → **整形は自分が書いたファイルだけを名指しする。** リファクタリングは
  「挙動を変えていない」ことを差分で示すのが仕事なので、無関係な行が
  混ざるとその証明が崩れる（レビューする側は全部読み直すことになる）。

- **切り出す根拠を「行数」にしない。** 493行だから割る、ではなく
  **「純粋な計算がコンポーネントに閉じ込められていて、板ごと描かないと
  試せない」**が根拠。実際、切り出して初めて `groupMoveChanges`
  （まとめて動かすと隊形が潰れないか）を単体で試せるようになった。
  逆に `positionsBySceneId[...] ?? {}` は45箇所あったが、**1行のストア
  読みなのでまとめなかった** — 触る危険の方が大きい。

- **リファクタリングで「既存のテストを書き換えない」ことが、そのまま証拠になる。**
  今回 StageContextMenu の12件は1行も触らずに通った。もし直していたら、
  挙動が変わったのかテストが甘くなったのか、後から区別できない。

- **1つの報告が、原因3つに分かれていた。**「ドラッグにダンサーが追ってこない、
  別のダンサーも移動する」は、①追随と確定で見ている物が違う ②移動アニメ中は
  掴めない印が区間の秒数まるごと立つ ③はみ出しの丸めが離した瞬間だけ、
  という**別々の3つ**だった。1つ直して「直った」にしていたら、残り2つが
  次の報告で戻ってくる。
  → **症状の数と原因の数は一致しない。** 報告の文を分解してから、
  ひとつずつコードで裏を取る（今回はどれも実装を読んで断定できた）。

- **見た目だけの食い違いは、ストアを見るテストでは捕まらない。**
  「他の人も動いて見えて、離すと戻る」は保存側では何も起きていない。
  直す前も後も、保存されるのは掴んだ本人だけ。
  → **捕まえたい壊れ方が「見た目」なら、テストは判断の分かれ目
  （選択がいつ切り替わるか）に当てる。** テストにも「これは何を見て
  いないか」を書いておく。

- **jsdom で dnd-kit を動かすには `pointermove` が2回要る。**
  距離8pxで起動する設定なので、1回目は起動に使われて移動量にならない。
  1回しか動かさないと、離した時の移動量が0のまま静かに通る（座標が
  変わらないので、テストは「動かないこと」を確認したように見える）。

- **Tailwind の任意メディアクエリは、前例が無いなら使わない。**
  `[@media(...)]` の形に `:flex` のようなユーティリティを続けるやり方は、
  クラス名を変数で組み立てると拾われず、空白の入れ方を1つ間違えると
  CSS がまるごと落ちる。しかも**どちらも画面を見るまで気づけない**
  （ビルドも lint も通る）。
  → 向きで出し分けるのが1箇所なら、素の CSS（`globals.css`）に置く。
  リポジトリに**動いている前例があるか**を先に確かめる。

- **確認ダイアログを流用するときは、文言まで見る。** 重なりの念押しに
  削除用の板をそのまま使うと、「この操作は元に戻せません」とゴミ箱の絵が
  出る。**戻せる操作を、取り返しがつかないものに見せてしまう**。
  → 板に `tone` を足して、絵・文言・ボタンの色を分けた。使い回す前に
  「その板が何を言っているか」を読む。

- **「遠いつもり」の点が、寄せ先の線の上に乗っていた。** 曲線の自動補間で
  「どちらからも遠ければ指の位置のまま」を確かめる試験を書いたら、選んだ点が
  たまたま直交する線の**上**で、吸着しても同じ値になるため**何も守って
  いなかった**（通ってしまう）。
  → **「効かないこと」の試験は、効いた場合と結果が変わる点を選ぶ。**
  座標を思い付きで置かず、寄せ先との距離を手で計算してから書く。

- **`SVGLineElement` のような構築子で分岐しない。** jsdom には無く、
  `instanceof` がその場で例外になる（テストで落ちて気づいた）。
  → 見た目の種類はタグ名で見る。**グローバルの有無に依存する判定を
  実装へ持ち込まない**（本番のブラウザでは動くので、テストが無ければ
  ずっと気づけない類い）。

- **ブラウザの対応状況を記憶で書かない。** 日本語の折り返しを直すとき、
  `word-break: auto-phrase` は Chrome 119+ だけで **iOS Safari は未対応**
  だった（caniuse で確認）。閲覧はスマホが主戦場なので、これだけでは
  半分しか直らない。
  → **効く範囲を先に調べてから設計する。** 調べた日付を残す。

- **数字の意味が「何で決まるか」を間違えると、片方の端で破綻する。**
  重なり判定をステージのユニットで持っていたので、**広いステージほど
  画面上のずれが大きく**なっていた。掴めるかどうかは丸の大きさ（px）で
  決まる話で、ステージが何ユニットあるかとは関係が無い。
  → しきい値を置くときは「**それは何の大きさと比べているのか**」を
  一度言葉にする。言えないなら単位が間違っている。

- **書く側だけ作って、読む側が無い機能は誰にも気づかれない。** 圏外での
  戻り道は、開くたびに端末へ控えていたのに**出す画面が作られていなかった**。
  型も lint もテストも通る（控える関数は使われているので「未使用」にも
  ならない）。台本には「戻り道が出る」と書いてあり、そこだけが嘘だった。
  → **控える / 出す のような対の機能は、片側だけで区切って終わりにしない。**
  出す側まで通してから、その日の作業を閉じる。

- **自分のファイルを除いた grep で「未使用」と判定しない。** 死んだ export を
  探して `grep -v <定義ファイル>` を掛けたら、**その中で使っている関数**が
  未使用に見えた。消してから型検査で気づいた。
  → 外から呼ばれていないだけなら、消すのではなく **`export` を外す**。
  「呼ばれていない」と「要らない」は別のこと。

- **控えや権限は「除くもの」ではなく「許すもの」を数える。** サービス
  ワーカーが、URL がエディタ（projects）で始まる画面だけを控えないように
  していたが、
  **トップページ `/` はログインしていると作品の一覧を描く**サーバーページで、
  そこから漏れていた（共有端末ならログアウト後も残る）。
  → 除外リストは**画面が増えるたびに漏れる**。守る側が少ないなら、
  そちらを数え上げる。増えたときに既定で漏れない形にしておく。

- **時間を「前のコマからの実測」で進めるなら、上限を置く。** 通し再生を
  rAF の差分で進めていたので、画面を消して戻すと**消していた間ぜんぶ**が

  叩いて測るを「区切りが2つ以上のときは出さない」と作った。理由は
  「どの区間を測ったのか読めない」で、それ自体は本当。だが**曲が
  変わる作品こそ、曲ごとの速さを測りたい** — いちばん要る場面で
  使えない物を出していた（user の報告「でてきません」）。
  → **口が2つになるなら、消すのではなく【どちらの物か画面から読める
  形】へ置き直す。** 今回は行の中へ移しただけで解決した。
  「2つある」が問題なのであって、「2つ目が要る」こと自体は正しい。

- **本番に出ているかは、user に聞く前に自分で確かめられる。**
  「でてきません」に対し、まず配信中のチャンクを grep して
  **文字列が本番に在ること**を確かめた（`curl` → `/_next/static/...`）。
  そこで「出ていない理由は配信ではない」と切れたので、残る候補が
  2つに絞れた。→ **画面の話をする前に、配っている中身を見る**
  （`.claude/rules/testing.md` 6節は dev サーバーの話だが、本番も同じ）。

- **`check:docs` は、差し込みの事故を捕まえる。**
  台本へ項目を差し込んだとき、元の項目の `n: true` の直後に入れて
  しまい、**同じ項目に `n` が2つ**できた（後ろが勝って前が消える形）。
  台本自身が警告していた事故を、自分で踏んだ。
  → **項目を差し込む「錨」は、`do:` の行ではなく `{` から書く。**
  `n:` が付いている項目があるので、`do:` を錨にすると前のキーを
  巻き込む。

### 同じ日の続き — 「使い方がわかりません」

- **案内の文が指しているものが、その画面から届くかを確かめる。**
  「曲に合わせて4回ほど叩いてください」と書いたが、曲のシートは
  画面全体を覆う板（`aria-modal`）なので、**開いている間は再生ボタンが
  押せなかった**。文は正しいのに、**その通りにできない**状態。
  → **手順を書いたら、その手順に出てくる物が同じ画面から触れるかを
  1つずつ当たる。** 「別の画面でやってから戻ってくる」は、書いていない
  限り伝わらない（Space では鳴らせたが、画面のどこにも書いていない＝
  無いのと同じ）。

- **「分かりません」は、機能ではなく【前提】が欠けている合図のことがある。**
  叩く機能そのものは動いていた。欠けていたのは**叩く相手**。
  → 使い方が伝わらないときは、**その操作に要る物が揃っているか**を
  先に数える。文言を練り直すより先。

- **molecule に状態を持たせたくなったら、props で受ける。**
  再生ボタンは `useUIStore` を読みたくなるが、`TapTempoButton` は
  molecule で**ストアに触れない**（`.claude/rules/frontend.md` 1節）。
  `isPlaying` と `onTogglePlay` を props で受け、organism 側が配った。
  **押す先は既存の `requestTogglePlay` ひとつ**なので、再生の口は
  増えていない（下のバー・Space・この板が同じ所を押す）。

- **文言を変えたら、その文を見ているテストが落ちる。** 今回は
  `tapTempoNote` を書き換えて1件落ちた。**落ちてよい落ち方**で、
  画面の字と台本・テストがそろっていることの裏返し。

### 同じ日の続き — 「その区間の音源を流す」

- **「再生する」は、どこから鳴るかまで決めないと役に立たない。**
  ▶ を足したとき、押す先を `requestTogglePlay` だけにした。だが再生は
  **縦線の居る所から**始まるので、2曲目の行の ▶ を押しても1曲目が
  鳴りうる。**測りたいのはその行の曲**なので、先に頭へ送る必要があった。
  → **「鳴らす」を足すときは、【どこから】を同じ手で決める。**
  位置を決めずに再生だけ足すと、たいてい思っていない所から鳴る。

- **持ち主が畳まれて消えることがある。**
  秒を動かすには `<audio>` が要る。`MusicTimeline` は `seekTo` を
  持っているが、**時間軸は畳むと外れる**（`isTimelineVisible`）。
  常に居るのは `SceneDock` の方。
  → **「この操作の持ち主は誰か」を、マウントされ続けるかまで見る。**
  持ち主が条件付きなら、頼みは届かないことがある。

- **名前を変えたら、その名前で書いた手順を全部数える。**
  「叩いて測る」→「クリックして測る」にしたとき、台本に14箇所＋仕様書に
  5箇所あった。**画面に無い名前を手順に残すと、また実行できない項目**に
  なる（前に一度やっている）。`check:docs` は文言キーは見るが、
  **地の文の言い回しは見ない**。
  → 名前を変えた日は `grep` で旧名を数え、**0 になるまで**直す。
  ただし**同じ字でも別の話**は触らない（「何も無いところを1回叩く」は
  選択解除の話で、無関係）。

### 同じ日の続き — 「どちらのボタンも反応してしまう」

- **同じ部品を並べたら、状態は「全体」ではなく「その1つ」で配る。**
  区切りごとに ▶ を置いたのに、渡していたのは**作品全体の
  `isPlaying`**。鳴り出した瞬間、どの行のボタンも一斉に ⏸ へ変わった。
  → **部品を並べた時点で、渡している props に「全体のもの」が混ざって
  いないか数える。** 1つだけのときは正しく見えるので、**並べるまで
  表に出ない**。

- **毎フレーム変わる値は、変わらない形へ畳んでから読む。**
  「その行が鳴っているか」は `currentTime` から出るが、秒をそのまま
  購読すると毎フレーム描き直しになる。**区間の番号**へ畳めば、
  境目をまたいだときしか変わらない。
  → 再生位置のような連続値は、**画面が要る粒度**まで落としてから配る。

- **端のない所で切らない。** 「その秒がどの区間か」を `fromSeconds`〜
  `toSeconds` で挟むと、**振付が終わって曲だけ続く間**がどの区間でも
  なくなり、ボタンがちらつく。見るのは `fromSeconds` だけにして、
  「その秒を過ぎた最後の区間」で1つに決めた。
  → **区間の判定は、隙間と外側で何が起きるかまで決める。**

- ⚠️ **置換スクリプトの門番が言うことを、出力で確かめる。**
  仕様書への追記が「当たらなかった」で終わっていたのに、その後の
  verify が緑だったので**書けたつもりで進みかけた**。門番は働いて
  いたが、**読んでいなかった**のはこちら。
  → 置換の直後に `grep -c` で**入ったことを数える**。
  「exit しなかった」ではなく「入った」を見る。
