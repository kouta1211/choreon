# Choreon UI仕様書（Claude Design 依頼用）

このドキュメントは、Choreon の現状のUIをデザイナー（Claude Design）に引き渡すための仕様書です。
実装の詳細（状態管理・フック・データ取得の仕組み）は意図的に含めていません。
「画面上に何があり、それが何を扱い、何が起きるか」だけを記述しています。

---

## 1. アプリの目的

**Choreon は、ダンスのフォーメーション（隊形）を作るためのスマートフォン向けアプリです。**

振付師やチームのリーダーが、曲の進行に合わせて「誰がステージのどこに立ち、次にどこへ、どのくらいの時間をかけて移動するか」を組み立て、再生して動きを確認できます。紙やホワイトボードで隊形図を描く作業を置き換えるものです。

中心にある考え方は3つです。

| 概念 | 意味 |
| --- | --- |
| **プロジェクト** | 1曲・1演目にあたる作業単位。ステージの広さ（マス数）を持つ |
| **シーン** | ある瞬間の隊形（フォーメーション）1コマ。順番を持ち、「このシーンへ移動してくるのにかかる秒数」を持つ |
| **ダンサー** | 演者1人。名前と色を持ち、各シーンごとに「位置(x, y)」「向き(角度)」を持つ |

つまりアプリは **「シーンの並び ＝ 隊形の絵コンテ」** であり、シーンを順に再生すると、ダンサーが次の位置へ滑らかに移動していくアニメーションになります。

### 想定利用シーン（デザインの前提として重要）

- **端末はスマートフォンが主**。練習場・スタジオで片手に持って使う
- 立ったまま、明るい／暗い両方の環境で使う（ダークテーマ固定なのはこのため）
- 操作は**指でのドラッグが中心**。細かい指定より「素早くざっくり置いて、あとで微調整」が主
- 1画面に「タイムライン（時間軸）」と「ステージ（空間）」の両方を同時に見たい、という要求が常にある

## 2. 画面構成

全4画面です。うち3画面は軽く、実質的な中心はエディタ画面（4番目）1つです。

| # | 画面 | パス | 役割 |
| --- | --- | --- | --- |
| 1 | ログイン | `/login` | メール＋パスワードでログイン |
| 2 | 新規登録 | `/signup` | メール＋パスワードで登録（確認メール送信の完了表示あり） |
| 3 | プロジェクト一覧 | `/` | 自分のプロジェクトの一覧と新規作成。ログアウト |
| 4 | **エディタ** | `/projects/[projectId]` | **本体。シーン編集・ダンサー配置・再生** |

### 共通のシェル

- 全画面ダークテーマ固定（OSのライト／ダーク設定は参照しない）
- ページ本文は中央寄せの**1カラム（最大幅 448px = `max-w-md`）**。ログイン／登録のみ 384px（`max-w-sm`）
- 画面2〜4の上部には共通ヘッダー（ブランド「Choreon」＋右側にページ固有のアクション）

## 3. 現在のコンポーネント構成（画面上の領域として）

### 3-1. エディタ画面の領域マップ

上から順に、1カラムに積み上がっています。

┌─────────────────────────────────────┐
│ A  アプリヘッダー                     │  ← ブランド ＋「プロジェクト一覧に戻る」
├─────────────────────────────────────┤
│ B  プロジェクトタイトル                │  ← 見出しテキストのみ
├─────────────────────────────────────┤
│ ┌ カード ─────────────────────────┐ │
│ │ C  シーンタイムライン              │ │
│ │   C-1 ズーム操作（右寄せ小アイコン） │ │
│ │   C-2 サムネイルストリップ（横スク） │ │
│ │   C-3 再生ボタン ＋ シークスライダー │ │
│ │   C-4 シーン操作バー               │ │
│ │ ─────────────────────────────── │ │
│ │ D  ダンサー追加フォーム            │ │
│ └───────────────────────────────┘ │
├─────────────────────────────────────┤
│ E  キャンバスツールバー                │  ← 左:トグル4つ ／ 右:元に戻す・やり直す
├─────────────────────────────────────┤
│ F  ステージ                          │
│    「バックステージ」ラベル             │
│    ┌───────────────────────────┐   │
│    │  グリッド／中心線／スナップ線   │   │
│    │  F-1 ダンサーマーカー          │   │

│    「客席側」ラベル                    │

│ G  ダンサーインスペクター（選択時のみ）  │

### 3-2. 各領域が扱うデータと操作

#### A. アプリヘッダー

- **表示するもの:** ブランドマーク（角丸の四角に「C」）＋ワードマーク「Choreon」
- **操作:** 右側に1つだけアクションが入る
  - エディタ画面 → 「プロジェクト一覧に戻る」リンク
  - プロジェクト一覧画面 → 「ログアウト」リンク
- **備考:** プロジェクト名はここには入れない（アプリ名と混同するため、ヘッダー直下に別の見出しとして置いている）

#### B. プロジェクトタイトル

- **表示するもの:** プロジェクト名。編集できることを示すため、点線の下線が付いている
- **操作:** タップするとその場が入力欄に変わり、名前を変更できる（Enter またはフォーカスが外れて確定、Escape で取消）

#### C. シーンタイムライン

エディタの時間軸側。**「どのシーンを今見ているか」を選ぶ**のが主目的です。

##### C-1. ズーム操作

- **表示するもの:** 縮小・拡大の小さなアイコンボタン2つ（右寄せ）
- **操作:** サムネイル1コマの幅を 64px 〜 160px の範囲で 16px 刻みに変える（既定 88px）
- **理由:** コマを大きくするとタップの的が広がり、隣のシーンを誤って選ぶことが減る
- **状態:** 下限／上限に達したボタンは無効（薄く表示）

##### C-2. サムネイルストリップ（横スクロール）

- **表示するもの:**
  - シーンを**ミニチュアのステージ**として横並びに表示。中には各ダンサーの位置が**色付きの点**だけで描かれる（名前・向きは出さない。小さすぎて読めないため）
  - 各コマの下にシーン名
  - コマとコマの**間**に「→ ＋ 秒数（例: `1.5s`）」のコネクタ。これは**表示専用**でクリックできない
  - 末尾に「シーンを追加」ボタン（破線枠＋ ＋ アイコン）
- **操作:**
  - コマをタップ → そのシーンを選択（＝ステージの表示が切り替わり、ダンサーがその配置へ動く）
  - 横スクロール → 止まった位置に一番近いコマを自動選択（1コマずつスナップして止まる）
  - コマを長めにドラッグ → シーンの並び替え
  - 「シーンを追加」 → 直前に見ていたシーンの配置をコピーした新しいシーンが末尾に追加され、そのまま選択される
- **状態:**
  - 選択中のコマ：枠がピンク、シーン名も太字ピンク
  - ドラッグ中のコマ：半透明で浮く
  - 追加処理中：追加ボタンが無効
  - スクロールバーは非表示（ノイズになるため意図的に隠している）

##### C-3. 再生ボタン ＋ シークスライダー

- **表示するもの:** 円形の再生／一時停止ボタン（ピンク）＋横いっぱいのスライダー
- **操作:**
  - 再生 → 現在のシーンから**最後のシーンまで**自動で進む。各シーンの遷移秒数ぶん待って次へ移る
  - スライダーをドラッグ → シーンを直接選ぶ（目盛りはシーン数ぶん、1刻み）
  - 再生中に手動でシーンを選ぶと再生は止まる
- **状態:** シーンが2つ以上あるときだけ表示される（1つ以下では出ない）

##### C-4. シーン操作バー（選択中シーンに対する操作）

- **表示するもの:** 鉛筆アイコン／タイマーアイコン＋秒数入力＋「秒」／（右端に）ゴミ箱アイコン
- **操作:**
  - 鉛筆 → シーン名の変更。押すとバー全体がインライン入力欄に**置き換わる**（Enter または フォーカスが外れて確定、Escape で取消）
  - 秒数入力 → **このシーンへ遷移してくるまでの所要時間**（0.1〜30秒、0.1刻み）。この値がステージ上の移動アニメーションの長さと、再生時の待ち時間の両方になる
  - ゴミ箱 → シーン削除（ブラウザ標準の確認ダイアログを出してから削除）
- **状態:** シーンが1つも選択されていないときは表示されない

#### D. ダンサー追加フォーム

- **表示するもの:** 1行のテキスト入力（プレースホルダ「ダンサー名」）＋「追加」ボタン
- **操作:** 名前を入れて追加すると、**選択中シーンのステージ中央**にダンサーが1人生まれる。色は6色パレットから自動で順番に割り当てられる
- **状態:** シーンが1つもないときは入力・ボタンとも無効

#### E. キャンバスツールバー

**左側：ラベル付きトグルスイッチが4つ**（折り返し可能な横並び）

  1. **シンメトリーモード** — オンの間、ステージ中央に縦の中心線が出る。ダンサーを動かすと、奥行き（Y座標）が最も近い相手が中心線を挟んだ鏡像位置へ連動して動く
  2. **導線を表示** — オンの間、選択中シーン → 次のシーンへの移動線をステージ上に描く
  3. **顔被りチェック** — オンの間、手前のダンサーに隠れて客席から見えないダンサーを警告色で塗る
  4. **グリッドを表示** — ステージの格子線の表示切り替え

- **状態:** 1〜3の初期値はオフ、4（グリッド）のみ初期値はオン

**右側：元に戻す／やり直す**

- **表示するもの:** 矢印アイコンのボタン2つ
- **操作:** ステージ上の編集（ドラッグ移動・矢印キーの微調整・向きの変更・曲線の変更）を1ステップずつ取り消す／やり直す。キーボードでは Ctrl/Cmd+Z ／ Ctrl/Cmd+Shift+Z（Ctrl+Y も可）
- **状態:** 取り消せる操作が無いとき、やり直せる操作が無いときは、それぞれ無効（薄く表示）
- **備考:**
  - 取り消し対象が別のシーンにある場合は、そのシーンへ自動的に切り替えてから戻す
  - 矢印キーの連続した微調整は1ステップにまとめられる（押した回数ぶん戻す必要はない）
  - シーンやダンサーの**削除は取り消せない**（確認ダイアログでカバーする方針）

#### F. ステージ

エディタの空間側。**上が「バックステージ（舞台奥）」、下が「客席側」** です。上下にその旨の小さなラベルが常に出ています。

- **形:** プロジェクトのマス数に応じたアスペクト比の長方形。ピンクの太い枠線
- **常に描かれるもの:** グリッド（1マス＝1ユニット＝実寸で約90cm想定）
- **条件付きで描かれるもの:**
  - **中心線** — シンメトリーモードON時。中央に薄いピンクの縦線
  - **スナップ線** — ダンサーをドラッグ中、格子線に吸着している間だけ、その線が発光したピンクでハイライトされる。縦横両方出ていれば交差点に吸着している
  - **暗幕** — 「マイ・フォーカス」中（後述）、ステージ全体がわずかに暗くなり、グリッドも薄くなる

##### F-1. ダンサーマーカー

- **見た目:** 真上から見た人物のシルエット。**円（頭）＋その先の小さな三角（鼻先＝向きの手がかり）**。ダンサーの色で塗られる。円の**下に名前**が常に正立して表示される（背景チップなし、テキストシャドウのみで可読性を確保）
- **操作:**
  - ドラッグ → 移動。8px 以上動かして初めてドラッグ扱い（軽いタップは「選択」になる）。指を離すと格子に吸着
  - タップ → 選択（→ インスペクターが開く）
  - 選択中に矢印キー → 微調整（通常 0.25 ユニット、Shift 併用で 1 ユニット）
  - 選択中に表示される**回転ハンドル**をドラッグ → 向きを変更。ハンドルは本体から46px離れた位置にある円形アイコンで、本体との間に破線のガイド線が引かれる。タップ領域は44px確保
- **重なる状態表示（同時に複数付きうる）:**

| 状態 | 見た目 | 意味 |
| --- | --- | --- |
| 選択中 | ピンクの実線リング | インスペクターを開いている一時的な状態 |
| キーボードフォーカス | ピンクの破線リング | 矢印キーで動かせる |
| マイ・フォーカス | 琥珀色の太いリング＋1.15倍に拡大／他のダンサーは30%まで減光 | 「自分（特定の1人）を目立たせる」状態。シーンを切り替えても維持される |
| 顔被り | 本体が警告赤に塗り替わる | 手前のダンサーに隠れている |
| 移動距離超過 | 右上に琥珀色の丸い警告バッジ（△） | 次のシーンへの移動が現実的な距離（約8m）を超えている。トグルなしで常時判定 |

##### F-2. 導線オーバーレイ

- **表示するもの:** 選択中シーン → 次のシーンへの移動軌跡を、**ダンサーの色に合わせた矢印付きの点線**で描く。複数人の線が交差する箇所＝ぶつかりそうな箇所を見つけるためのもの
- **操作:**
  - 選択中のダンサーの線にだけ、**制御点のハンドル**が出る。これをドラッグすると線が曲線に曲がる
  - ダブルクリックで直線に戻る
- **ハンドルの構造:** 見た目は直径14pxの円（ダンサーの色＋白フチ）だが、タップ領域は44px確保している。軽く触れただけ（4px未満の移動）では制御点を確定せず、ドラッグしたときだけ曲線になる
- **重要:** ここで描いた曲線は見た目だけではなく、**実際の再生でもダンサーはこの線の通りに動きます**

#### G. ダンサーインスペクター

ステージ上のダンサーをタップすると、ステージの**下に**現れる横1行のパネルです。

- **表示するもの（左から順に）:** ダンサー名 ／ 6色のカラーチップ ／ タイマーアイコン＋秒数入力 ／ フォーカスボタン ／ 削除ボタン ／ 閉じるボタン
- **操作:**
  - ダンサー名 → タップするとその場が入力欄に変わり、名前を変更できる（Enter で確定、Escape で取消）。編集できることを示すため点線の下線が付いている
  - カラーチップ → ダンサーの色を変更（選択中の色にはピンクのリング）
  - 秒数入力 → **このダンサー・このシーンだけ**の遷移時間の上書き。空欄ならシーンの既定値を使う（プレースホルダに「既定1」のように既定値が出る）。「この人だけ先に到着／遅れて到着」という演出のため
  - フォーカスボタン → 「マイ・フォーカス」のON/OFF。ONの間、このダンサーだけが強調されて他が減光する
  - 削除 → 確認ダイアログののち削除
  - × → 選択解除（パネルが閉じる）
- **状態:** ダンサーが選択されていないときは領域ごと存在しない（＝レイアウトが上に詰まる）

#### H. トースト

- **表示するもの:** 画面下部中央に浮く小さな帯。4秒で自動的に消える
- **種類:** エラー（赤）／成功（緑）。実際にはほぼエラー通知にのみ使われている（「位置の保存に失敗しました」など）

現状の実装から抽出した「事実」です。デザインの出発点として使ってください。

### 4-1. ベースカラー

| 用途 | 値 |
| --- | --- |

### 4-3. アクセント：ピンク

**唯一のブランドアクセント色**として、以下すべてに一貫して使われています。

| トークン | 使われ方 |

### 4-9. 既知の不整合（デザイン時に把握しておいてほしい点）

- **フォントが意図通りに効いていません。** Geist Sans / Geist Mono を読み込んでCSS変数として定義しているにもかかわらず、`body` に `font-family: Arial, Helvetica, sans-serif` が直書きされているため、**実際の表示は Arial / Helvetica です。** タイポグラフィを設計する際は、Geist を使う前提にするのか別のフォントにするのかを明示してください
- **秒数の入力欄が2箇所（シーン用・ダンサー個別用）にあり、見た目が同じです。** どちらの秒数を編集しているのか区別しづらい状態です
- **「編集できるテキスト」の表現が点線の下線しかありません。** プロジェクト名・ダンサー名がこれにあたり、押せることが伝わりにくい状態です

## 5. デザインし直したい範囲

**全画面が対象です。** 現状は機能を積み上げた結果のレイアウトで、視覚的な設計を一度も通していません。

### 5-1. 特に手を入れてほしいところ（優先度順）

1. **エディタ画面のシャーシ全体**
   縦に積むだけの構成のため、スマートフォンの1画面にステージとタイムラインが収まりきりません。「時間軸（タイムライン）」と「空間（ステージ）」という**性質の違う2つの主要領域**をどう共存させるかを設計し直してほしい領域です。
   - シーンタイムラインとダンサー追加フォームが同じカードに同居している現状の区切りは、意味的におかしいので変えてよい
   - シーン操作バー（C-4）とキャンバスツールバー（E）とインスペクター（G）が、いずれも「小さなアイコンが並ぶ横一列」で見た目が似ており、役割の違いが伝わっていない。ツールバーはトグル4つと元に戻す／やり直すを1行に同居させており、特に窮屈になっている
   - トグル4つ（シンメトリー／導線／顔被り／グリッド）は、性質の違うものが同列に並んでいる。「編集モードの切り替え」と「表示物のON/OFF」を分けるなど、グルーピングの提案を歓迎します
   - インスペクター（G）が出入りするとレイアウト全体が上下に動く。この扱いも含めて再設計してよい

2. **ステージ上の表示物**
   状態表示（選択／キーボードフォーカス／マイ・フォーカス／顔被り／移動距離超過）が**最大5種類同時に重なりうる**にもかかわらず、リングとバッジの積み重ねで表現しています。ここの視覚言語を整理してほしい。
   - ダンサーマーカー本体、名前ラベルの可読性、警告の出し方
   - 導線（点線＋矢印＋制御点ハンドル）の見え方。人数が増えると線が渋滞する
   - スナップ線・中心線・グリッドという3種類の「補助線」の階層づけ

3. **プロジェクト一覧・作成フォーム**
   現状は枠線だけのカードが並ぶ最小限の見た目。プロジェクトのサムネイル（代表シーンの隊形）や更新日時など、**カードに載せるべき情報の提案も歓迎**します。

4. **ログイン／新規登録画面**
   汎用のカード＋フォームで、Choreon らしさが全くありません。ブランドの第一印象を担う画面として作り直してほしい。

### 5-2. 状態バリエーションも設計対象

以下は現状ほぼ手当てされていません。デザインに含めてください。

- **空状態:** プロジェクト0件／シーン0件（「シーンがありません。上のタイムラインから作成してください。」というテキストのみ）／ダンサー0件
- **処理中:** 送信中のボタン、シーン追加中
- **エラー:** トースト、フォーム内エラーテキスト
- **確認ダイアログ:** シーン削除・ダンサー削除は**ブラウザ標準の `confirm()`** を使っており、見た目がアプリから浮いています。アプリ内のモーダルに置き換える前提でデザインしてよい

## 6. 触ってほしくない範囲（前提として維持してほしいもの）

以下は**変更しないでください**。機能そのもの、あるいは確定済みの方針です。

### 6-1. ステージの座標系とアスペクト比

- ステージはプロジェクトの「マス数（横×縦）」からアスペクト比が決まる長方形で、ダンサーはその中に**パーセント指定で配置**されます
- **1マス＝1ユニット＝実寸で約90cm**という対応関係を持ちます。グリッドの分割数を装飾都合で変えないでください
- ステージの縦横比・座標の考え方・グリッドの意味を変えると、位置計算・格子スナップ・移動距離の判定がすべて壊れます
- 「上＝バックステージ／下＝客席側」という向きの規約も固定です

### 6-2. ダークテーマ ＋ ピンクアクセントという配色方針

- `#19191c` ベースのダーク1本（ライトテーマは作らない）
- アクセントは `pink-500` 系。インディゴなど別の色相への変更はしないでください
- グレーは zinc スケールで統一する方針を維持
- ※ 個々のトーンの調整（どのグレーをどこに使うか、ピンクの濃淡の使い分け）は**自由に見直してかまいません**。変えないでほしいのは「ダーク＋ピンク」という色相の方針です

### 6-3. 操作方法（インタラクションの仕組み）

見た目は変えてよいですが、**操作の仕組み自体は変えないでください**。

- ダンサーは**ドラッグで移動**（8px 動いて初めてドラッグ扱い、軽いタップは選択）
- 向きは**選択中に出る回転ハンドルをドラッグ**して変える
- シーンの並び替えは**サムネイルを直接ドラッグ**
- シーンの選択は**タップ／横スクロール／スライダー／再生**の4通り
- 導線の曲線は**制御点ハンドルのドラッグ**で編集、**ダブルクリックで直線に戻す**
- タップ領域は最低44pxを確保する（回転ハンドルなど）

### 6-4. スマートフォン最優先・1カラム

- **スマートフォン縦持ちが第一の対象**です。まずスマホで成立するデザインを作ってください
- 現状の「最大幅448pxの1カラムに全部収める」前提を維持します。タブレット／デスクトップ向けの2カラム化やサイドパネル化は今回のスコープ外です

### 6-5. 文言

- UIの表記はすべて日本語です。既存の文言（「バックステージ」「客席側」「シンメトリーモード」「顔被りチェック」「マイ・フォーカス」など）はドメイン用語なので、そのまま使ってください
