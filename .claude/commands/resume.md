---
description: 前回の続きから作業を再開する。いまの位置・前回の引き継ぎ・宙に浮いたままのことを集め直し、最初の一手を1つ決める
---

新しいセッションで「前回の続きをしましょう」と言われたら、以下を自律的に実行してください。

1. **足元を測る:** git・開発サーバー・落ちているものを、**機械が答えられる範囲だけ**確かめる。
2. **引き継ぎを読む:** 記憶の再開地点と直近の学びから、【次の一手】【持ち越し】【user へ投げたまま返事をもらっていないこと】を拾う。
3. **再開票を出す:** 「いまの位置 / 前回の続き / user に決めてほしいこと」を短く出し、**最初の一手を1つ勧める**。
4. **着手する:** 決まった一手をそのまま始める。ここで改めて許可を取らない。

---

## 0 いちばん先に見るもの

**user が一緒に何か言っていれば、それが正。** 「続きを」に主語が付いて
いるなら（「昨日の共有シートの続き」など）、下の収集はその周りだけでよい。

## 1 で実際に見るもの

**全部を読み直さない。** 機械に聞けば済むものだけを聞く。

```bash
git status --short              # 未コミットの変更（あれば、これが最優先）
git status -sb | head -1        # origin より進んでいないか（ahead N）
git log --oneline -12
git worktree list               # 前回の worktree が残っていないか
```

- **未コミットの変更があれば、そこから。** 前回が途中で切れている。
  中身を読んで、続きなのか落とし物なのかを見分けてから動く
- **`ahead N` は「この端末にしか無い」という意味。** 伝えるだけでよい
- 前回の作業日ぶんを見るなら、**朝5時で日を切る**
  （`scripts/workday.mjs`。`/wrap-up` と同じ切り方）

**開発サーバーは、生きているかだけでなく【中身が新しいか】まで見る。**

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/ || echo "立っていない"
```

立っていないときは `000` を出して**この行自体が失敗する**（curl の exit 7）。
`&&` で後ろに繋ぐと、後段が黙って飛ぶので繋がない。
**立っていなければ、それでよい。** user が要ると言うまで立てない。

生きていても**古いものを返し続けることがある**（2026-08-20 に2回）。
見分け方と直し方は `.claude/rules/testing.md` の6節。
**画面の話を始める前に、必ずここを通す。**

### `npm run verify` を回すか

**毎回は回さない。** lint・テスト・build で待つ間に、読めるものがある。

| いまの状態 | どうする |
| --- | --- |
| ツリーが空で、引き継ぎに「緑で終わった」と残っている | **回さない。** その記録を信じる |
| 未コミットの変更が残っている | **回す。** 何が落ちているか分からないまま重ねない |
| 「緑」の記録が無い / 前回から何日か空いている | **回す** |
| 依存や土台が触られている（`package.json`・`schema.sql`） | **回す** |

回さないと決めたときは、**回していないことを再開票に書く**。
「緑です」と言い切らない。

## 2 で読むもの（順に、要るところで止める）

1. **記憶の再開地点** … セッションの頭に読み込まれる記憶の索引に、
   再開地点を指す行がある。その**ファイル本体**を開く（索引には要約しか
   載っていない）。【次の一手】【持ち越し】【その日に決めた作法】はここ
2. `docs/lessons_learned.md` の**末尾だけ**。前回の日付の見出しから下
3. 規約（`.claude/rules/`）は、**一手が決まってから、その層だけ**

拾うのは3つ。混ぜない。

- **次の一手の候補** … 前回が「次はこれ」と書き残したもの
- **持ち越しと未決** … 「やらないと決めた」ものと「まだ決まっていない」ものは
  別物。前者を蒸し返さない
- **user へ投げたまま返事をもらっていないこと** …
  **これが最優先。** 答えを待っている間に別の所を触ると、返事が来たときに
  作り直しになる。再開票の先頭で聞く

**台本の「今日の分」の印は、その日の最初に落とす。** 前の日の分が
残ったままだと、絞っても絞れない（`docs/qa-checklist.html` の `n: true`）。
手順は `.claude/skills/qa-checklist/SKILL.md`。

**引き継ぎが実際と食い違っていたら、その場で直す。** 再開地点が古い
コミットを指していたら書き換える。放っておくと、次のセッションも同じ
勘違いから始まる。

## 3 の再開票

**読む時間が作業を食わない長さで。** 出すのは3つだけ。

- **いまの位置** … コミット・ツリー・（回したなら）verify の結果
- **前回の続き** … 候補は**多くて3つ**
- **user に決めてほしいこと** … 待たせている返事・未決の宿題

そのうえで**最初の一手を1つ勧める**。候補を並べるだけでは、選ぶ手間を
user へ渡しただけになる。**「おすすめの順で」と返ってきたら、
そのまま始めてよい。**

**分からないものを埋めない。** 前回の会話は残っていない。
git log と引き継ぎに書いていないことは、**書いていないと言う。**

## やらないこと

- **前回の差分を読み直して要約しない。** コミットメッセージが既にそれ
- **持ち越しを勝手に始めない。** 「やらない」と決めたものが混ざっている
- **設計の相談から始めない。** 手が動く小さいものが残っているなら、そこから
- **`/wrap-up` の逆をやろうとしない。** 締めは【記録】、再開は【選択】。
  集めるのは、選ぶために要るものだけ
