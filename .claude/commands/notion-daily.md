description: その日のGitコミット履歴や教訓ログを集計し、Notion API経由で日報ページを自動生成する
---

本日の開発実績を集計し、Notionに日報を投稿するため、以下のステップを自律的に実行してください。

1. **本日の実績・差分の取得:**
   - **「本日」は 0:00 ではなく朝5時で切る**（`node scripts/workday.mjs`）。
     深夜の作業は前日の日報に入れる。下の「日付の切り方」を必ず読む。
   - `git log --since="$(node scripts/workday.mjs --since)" --until="$(node scripts/workday.mjs --until)" --oneline`
     を実行し、その作業日のコミット一覧を取得する。
   - 本日作成・更新された仕様書（`docs/features/` 配下）や `docs/lessons_learned.md` の追記分を取得する。
2. **日報コンテンツ（Markdown）の生成:** 下の「既存の形に合わせる」に従って本文を構築する。
3. **Notion への投稿:** 下の「投稿の2通り」に従う。手元で回すなら Notion の MCP、
   無人で回すなら API（`NOTION_API_KEY` / `NOTION_DATABASE_ID`）。
4. **結果の報告:** 「本日の開発日報をNotionに自動投稿しました！お疲れ様でした。」と作成したページの URL を出力して完了する。

---

## 日付の切り方（0:00 では切らない）

**深夜0時を回ってからの作業は、前日の日報に入れる**（2026-08-18 の user の指示）。
日付は 0:00 で変わるが**作業は 0:00 では終わらない**ので、
翌日のページに1行だけ迷子で載っても意味が読めない。

日の変わり目は**朝5時**。出すのは `scripts/workday.mjs` の1箇所だけで、
**自分で `date` を打たない・壁の時計を写さない。**

```bash
node scripts/workday.mjs            # いまの作業日  → 2026-08-18
node scripts/workday.mjs --since    # その始まり    → 2026-08-18 05:00:00
node scripts/workday.mjs --until    # その終わり    → 2026-08-19 05:00:00
```

- `--date` へ渡すのも、`git log` の範囲も、**同じここから取る**。
  片方だけ手で書くと、境目の日に**コミットとページの日付が食い違う**
- 5時にしたのは、**保守点検が朝5時に回っている**から。変わり目を2つ
  持たない。変えるなら `WORKDAY_START_HOUR` の1箇所
- 確かめたいときは `--at "2026-08-19T02:00"` を足すと、その時刻での答えが出る

## 指示から変えたこと

| 変えた所 | なぜ |
| --- | --- |
| `docs/02_features/` → **`docs/features/`** | 前者は存在しない |
| タイトル `YYYY-MM-DD 開発日報` → **`YYYY-MM-DD`** | 既存の日報が全部この形。混ぜると一覧で揃わない |
| 本文の見出し | 既存の3節に合わせる（下記） |
| 投稿は API 一択 → **MCP を優先** | 手元で回すぶんには鍵の設定が要らない |

## 投稿先（調べ済み・2026-08-18）

- データベース: **開発日報** `c1aba594-8aa4-4c6b-b8ee-51fe11e8da54`
  （データソース `collection://15f72ffe-85c6-4f6e-9c7d-2be0402217fe`、
  親は「note_プログラミング」）
- プロパティ:

| 名前 | 型 | 入れる値 |
| --- | --- | --- |
| `Name` | title | **`YYYY-MM-DD`**（日付だけ。既存がそう） |
| `日付` | date | 同じ日付 |
| `プロジェクト` | select | Choreon は **`フォーメーションアプリ`** |
| `ステータス` | select | `順調` / `やや停滞` / `詰まっている` |
| `概要` | text | 一行。一覧に出るのはこれ |

**`ステータス` は正直に付ける。** 詰まった日に `順調` を入れると、
後から読み返したときに記録として使えなくなる。判断の目安:
`詰まっている`＝解けていない問題を持ち越した／`やや停滞`＝手戻りが大きかった
／`順調`＝進んで、詰まりも解けた。

## 既存の形に合わせる

本文は**既存の3節をそのまま使い、最後に1節だけ足す**。

```markdown
## 進んだこと・学んだこと
- <コミットから。ハッシュではなく、何が変わったかを人の言葉で>

## 詰まった点・課題
**問題:** <何が起きたか>
**原因:** <なぜ起きたか>
**解決法(or 未解決):** <どう直したか。直っていないならそう書く>

## 所感・振り返り
- <lessons_learned.md に今日追記したぶんから>

## 明日へ・申し送り
- <次に何から始めるか。未コミット・未 push があればそれも>
```

- **詰まらなかった日は「詰まった点」を空にせず「特に無し」と書く。**
  3行の型（問題/原因/解決法）は残す
- **コミットのハッシュを並べない。** git log を見れば分かる。
  日報に要るのは「何が変わったか」
- **`明日へ・申し送り` は既存には無い節。** 足す価値があると判断したが、
  要らなければ消してよい

## 投稿の2通り

### A. 手元で回すとき（既定・準備は要らない）

Notion の MCP が繋がっている（`syumonoy` / masutema1211@gmail.com）。
`notion-create-pages` に上のデータソースと properties を渡す。**鍵の設定は不要。**

### B. 無人で回すとき（夜のルーティン）

MCP は user の対話ログインに紐づいているので、**無人実行では使えない。**
そのときは `scripts/notion-daily.mjs` を使う（本文は標準入力から）。

```bash
node scripts/notion-daily.mjs --date "$(node scripts/workday.mjs)"   --status 順調 --summary "一行の概要" < body.md
```

- `--dry-run` を付けると**通信せず**、送るはずの JSON とブロック数を出す。
  **形を変えたら、まずこれで確かめる**
- 同じ日の**同じプロジェクト**のページが既にあれば、**新しく作らずそこへ追記する**
- Markdown → ブロックの変換は `scripts/notionBlocks.mjs`（テストあり）。
  見出し `##` / 箇条書き `-` / 段落 / `**太字**` の4つだけ対応

事前に必要なもの:

1. **https://app.notion.com/developers/connections** を開く →
   左の **Build → Internal connections** → **Create a new connection**。
   名前を付けてワークスペースを選ぶ
   （2026-08-18 に確認。以前の `my-integrations` と「新しいインテグレーション」は
   **もう無い**。Notion 側の名前が変わっている）
2. **鍵は Configuration タブの「Installation access token」**
3. **アクセスを与える。** 同じ画面の **Content access タブ → Edit access** で
   「開発日報」を選ぶのが早い（Notion 本体の ••• → Connections →
   + Add connection でも同じ）。**ここを忘れると `object_not_found` になる**。
   鍵が正しくても見えない（スクリプトはこのとき直し方を名指しで出す）
4. `.env.local` に2つ入れる（`.env.example` に雛形あり）

```bash
NOTION_API_KEY=ntn_xxxxx
NOTION_DATABASE_ID=c1aba5948aa44c6bb8ee51fe11e8da54
```

### 夜のルーティンから呼ばれたとき

無人で走っているので、**迷ったら投稿しない**。

- コミットが0件 → 投稿せず終わる
- `git log` が読めない・鍵が無い → **投稿を作らず、その事実だけを残す**。
  中身の薄い日報を1本作る方が害が大きい
- ステータスは正直に付ける。**無人だからといって全部「順調」にしない**

## 投稿の前に

- **同じ日の【同じプロジェクトの】ページがあるか確かめる。** あれば新規作成せず、
  そのページへ追記する。**日付だけで一致を見ない** — このデータベースには
  複数のプロジェクトの日報が入っていて、**同じ日付のページが並ぶのが正常**
  （2026-08-19 に user から指摘。それまで日付だけで探していた）。
  日付だけで探すと、よそのプロジェクトの日報へ追記してしまう
- **コミットが0件の日は投稿しない。** 「今日は何もありませんでした」の
  ページが並ぶと、一覧が読めなくなる。その旨だけ報告して終わる
- **未コミット・未 push があれば、申し送りに書く**

## 無人で回すのは、いまは保留（2026-08-18 に試して分かったこと）

**夜のクラウドルーティンを作って2回走らせたが、投稿できなかった。**
無人セッションでは、投稿の経路が**両方とも塞がっている**。

| 経路 | 無人で使えるか | なぜ |
| --- | --- | --- |
| Notion の MCP | **使えない** | コネクタを trigger に付けても、**セッションに道具が渡らない**（実行ログの `ToolSearch` で確認。GitHub の道具は出たが Notion は0件） |
| `.env.local` の鍵 | **使えない** | リポジトリを clone して動くので、gitignore してあるファイルは存在しない |
| クラウド環境の環境変数 | 置けるが**非推奨** | 公式に「cloud environments have no dedicated secrets store, so don't add API keys or other credentials」とある |

**いまは `/wrap-up` から手元で投稿している。** 1日の締めに1語打つだけで、
鍵の管理も要らない。ルーティンは作ってあるが**止めてある**
（名前に理由を書いてある。消さずに残しているのは、次に同じことを
調べ直さないため）。

### 無人にしたくなったら

- **A. クラウド環境の環境変数に鍵を置く** … 2分で動く。ただし平文で保存される。
  個人の環境で、鍵が「開発日報」1つにしか触れないことを理解したうえで選ぶこと

解かないこと。

## うまくいかないときの見分け方

| 出たもの | 原因 |
| --- | --- |
| `データベースが見つかりません` | インテグレーションへの**接続を忘れている**（鍵は正しい） |
| `鍵が受け付けられませんでした` | `NOTION_API_KEY` の貼り間違い |
| `NOTION_API_KEY がありません` | `.env.local` に入っていない／無人実行から見えていない |
| `本文が空です` | 集計の結果が空。**投稿しないのが正しい** |
