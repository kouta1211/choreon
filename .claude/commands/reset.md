---
description: 会話履歴をリセットする前に、未保存の作業や学習ログがないか安全確認を行う
---

ユーザーがセッションをリセットする前に、以下のステップを自律的に実行してください。

1. **未コミット変更の確認:** `git status` を実行し、未コミットの変更があれば「⚠️ 未コミットの変更があります。先に `/commit` を実行して保存してください」と警告し、処理を停止する。
2. **学習ログの取りこぼしチェック:** 今日のセッションで得た教訓が `docs/lessons_learned.md` に記録されているか確認する。もし記録されていなければ、裏で自律的に学習内容を抽出し、ファイルに追記する。
3. **リセットの案内:** 全てのデータが安全に永続化されたことを確認後、以下のメッセージを出力する。
   「✅ 全ての作業と学習ログの保存が完了しました。
   パフォーマンスを最高状態に保つため、`/clear` コマンドを実行するか、Claude Codeを再起動して会話履歴をリセットしてください。次のタスクでお待ちしています！」

---

## 1 で実際に見るもの

```bash
git status --short
git status -sb | head -1        # origin より進んでいないか（ahead N）
```

- **未追跡ファイル（`??`）は中身を見てから言う。** 作業の成果なのか、
  落とし物（画像・書き出し・ログ）なのかで意味が逆になる。
  落とし物なら「消してよいか」を聞く。**勝手に消さない**
- **`ahead N` なら止めなくてよい。** コミット済みなら消えない。
  ただし「この端末にしか無い」ことは伝える
- 停止するのは**未コミットの変更があるとき**だけ

## 2 の判断（`/wrap-up` と重ねない）

**`/wrap-up` を先に回していたら、2 はやらない。** 同じ教訓が二重に載る。

| いつ | 使うもの |
| --- | --- |
| その日の終わり | **`/wrap-up`**（振り返り＋引き継ぎ）。そのあと `/reset` は要らない |
| 作業の途中で、話が長くなったので畳みたい | **`/reset`** |

途中の `/reset` で書くのは、**次に同じ判断をするときに要るもの**だけ。
「今日やったこと」の一覧は git log にある。**書くことが無ければ書かない。**

## リセットで本当に失われるもの

`/clear` しても、`CLAUDE.md` と `.claude/rules/` と `docs/` は次のセッションで
読み直される。**消えるのは「この会話でだけ決めたこと」**。だから 3 の前に、
次の3つがファイルに残っているかを見る。

1. **次に何から始めるか。** 記憶ファイルの再開地点、または
   `docs/lessons_learned.md` の末尾に一行
2. **やらないと決めたこと。** これが消えると、次のセッションが
   取り下げ済みの案を蒸し返す
3. **user へ聞くつもりだったこと。** 宙に浮いたまま消えると、二度と出てこない

**どれかが口頭の合意のままなら、書いてからリセットを勧める。**

## 動いているものの確認

```bash
git worktree list                                   # 作業用の worktree が残っていないか
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/   # 開発サーバー
```

- **自分が立てた開発サーバーは、user へ伝える**（止めるかは user が決める）
- 走らせたままのバックグラウンド処理があれば、終わったか確かめてから案内する
- **worktree を残さない。** 残すと次のセッションが混乱する
  （`node_modules` を junction で持ち込んだ worktree は、削除で本体を壊す）
