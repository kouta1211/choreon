---
description: 巨大なファイルを、単一責任の原則に従って安全かつ型厳格に分割・再構築する
---

ユーザーが指定した巨大なコンポーネントやロジックに対し、以下のステップで自律的にリファクタリングを実行してください（許可不要）。

1. 事前に `/analyze` 相当の調査を行い、影響範囲を把握する。
2. 「UI表示（View）」「状態管理・API通信（Hooks/ロジック）」「型定義（Types）」に関心事を分離し、ファイルを分割して作成する。
3. 分割後も既存の動作が一切変わらないよう、`any` を排除した厳格な型定義で各ファイルを繋ぎ合わせる。
4. 静的解析（lint、型チェック）を実行し、エラーが出た場合は完全に解消するまで自己修正を行う。

---

## 0. 割る前に、テストで縛る

**「動作が一切変わらない」を保証できるのは、通っているテストだけ。**
目視でも型でもない。だから順番はこうなる。

```
テストが無い → まず【いまの挙動を写し取るテスト】を足して、通す（この時点では何も直さない）
             → それから割る
             → 同じテストが通ることを確認する
```

先に割ってから書いたテストは、**割った後の姿を写しただけ**で、
挙動が変わったことを教えてくれない。順番を逆にしない。

## 1. 勘で割らない

このリポジトリの過去のリファクタリングは
「**測って見つけた3箇所**」（`9f7dfbc`）という単位で入っている。
行数が多いだけで割らない。割る根拠は次のどれか:

- **同じ形が3箇所以上に書かれている**（`git grep` で数える）
- **関心事が明らかに混ざっている**（純粋な計算とストアの更新が同じ関数に居る）
- **テストが書けない**（DOM とロジックが絡んでいて、切らないと確かめられない）

根拠が言えないなら、割らずにそのままにする。

## 2. このリポジトリの「関心事の分け方」

指示の View / ロジック / Types は、この構造に対応させる。

| 何 | 置き場所 |
| --- | --- |
| **純粋な計算**（DOM にも Supabase にも依存しない） | `src/features/<domain>/lib/` ← **いちばん重要。ここへ出す** |
| そのドメインの操作 | `src/features/<domain>/hooks/` |
| Supabase とのやり取り | `src/features/<domain>/api/` |
| 型 | `src/features/<domain>/types.ts` |
| 見た目だけ | `src/components/atoms` / `molecules` |
| ストアを読む・書く | `src/components/organisms` |

**計算をコンポーネントの隣の `utils.ts` に出さない。** `lib/` へ出すと
テストが書けるようになる（それがこの分け方の目的）。層の判断基準は
「**Zustand のストアに触るか**」で、詳しくは `src/components/README.md` と
[.claude/rules/frontend.md](../rules/frontend.md)。

**依存は下向きだけ**（organisms → molecules → atoms）。
molecules がストアを読み始めたら、それは organisms へ戻す合図。

## 3. 繋ぎ直すときに守ること

- **`any` を使わない。** 逃げ道が要るなら `unknown` + 絞り込み
- **`export` を増やしすぎない。** 分割の副作用で内部だけの関数が
  公開されがち。外から呼ばないものは `export` しない
- **コメントを一緒に運ぶ。** このリポジトリは「なぜそうしたか」を
  コメントで残す方針。切り出した先へ持っていく。置き去りにすると、
  次に読む人が理由を失う
- **`data-testid` を変えない。** テストと台本が名指ししている

## 4. 確かめる

```bash
npx tsc --noEmit
npm run verify        # lint → test → build
```

**テストの数が減っていないか**も見る（消えたテストは、消えた保証）。

## 5. 出し方

**挙動を変えない変更だけで1つのコミットにする。** 直したいものが
一緒に見つかっても、混ぜない（混ぜると「動かなくなった」ときに
どちらが原因か分からなくなる）。メッセージは
`リファクタリング（挙動は変えない。…）` の形に揃える。

**画面に見える変更が無いなら、`docs/qa-checklist.html` は更新しない**
（内部の整理だけなら更新しない、という決まり。項目が増えるほど
一巡が重くなる）。逆に、少しでも見え方が変わったなら `/qa-checklist` を回す。

## やらないこと

- `choreon-app/`（Expo・停止中）を巻き込む。ESLint の対象外なので、
  壊しても `npm run verify` は黙る
- 「ついでに」の挙動変更。見つけたら**別のコミット**か、報告に回す
- テストが無いまま割る（0 に戻る）
