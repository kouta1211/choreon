description: 現在のブランチの差分から完璧なプルリクエストの概要を生成し、GitHubにPushしてPRを作成する
---

作業完了後、以下のステップを自律的に実行してください（すべて許可不要）。

1. `git push origin HEAD` を実行し、現在のブランチをリモートにPushする。
2. コミット履歴とコードの差分を分析し、「目的」「変更内容」「重点的にレビューしてほしいポイント」「関連する仕様書」を含む、プロフェッショナルなPRのMarkdownテキストを生成する。
3. ローカル環境に GitHub CLI (`gh`) がインストールされているか確認する。
4. `gh` が利用可能な場合、生成したテキストを用いて `gh pr create --title "<タイトル>" --body-file <一時ファイル>` を実行し、実際のPRを作成する。
5. 作成されたPRのURL、または（`gh`が無い場合は）生成したPR用のMarkdownテキストを出力して完了する。

---

## 1 の前に、必ず止まる条件

```bash
git branch --show-current
git status --short
```

- **`main` に居たら、push も PR も作らない。** `main` から `main` への PR は
  作れない。**先に `/branch` で切ってから**、と伝えて止まる
  （このリポジトリは既定で main へ直接コミットしている運用なので、
  ここへ来る時点で取り違えている可能性が高い）
- **未コミットの変更があれば先に止める。** push しても入らないので、
  PR の中身と手元がずれる。`/commit` を促す
- **`npm run verify` を通してから push する。** CI は `main` 向けの PR で
  走るが、落ちてから気づくと往復が1回増える

## 2 の本文の形

```markdown
## 目的
<何を解決するのか。困っていたことから書く>

## 変更内容
- <何をどう変えたか。ファイル名の羅列にしない>

## 重点的に見てほしいところ
- <path:line — なぜ迷ったか、他の案は何だったか>

## 確認したこと
- npm run verify — 通過（テスト NNN 件）
- <実機で見たなら、何をどう見たか>

## 関連
- 仕様: docs/features/<...>.md
- 決定: docs/architecture/decisions/<...>.md
- 台本: docs/qa-checklist.html の <章>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

守ること:

- **「重点的に見てほしいところ」を空にしない。** 迷わなかったなら
  「特に無し」と書く。埋め草を書かない
- **確認したことに、やっていないことを書かない。** 実機で見ていないなら
  「実機未確認」と正直に書く。そこが user のレビューの起点になる
- **差分の要約ではなく、判断を書く。** 差分は GitHub が見せてくれる。
  PR に書く価値があるのは**選ばなかった案と、その理由**

## 4 の実行

```bash
gh pr create --title "<タイトル>" --body-file <一時ファイル> --base main
```

- 本文は**一時ファイル経由**（`--body` に長文を渡すと改行が壊れる）。
  一時ファイルはスクラッチパッドへ置く（リポジトリを汚さない）
- タイトルはコミットと同じ作法 — **日本語・プレフィックス無し・何をしたか一文**
- **`--draft` を既定にしない。** レビューを待つ状態にする

## PR を出したあと

**マージはしない。** user が読んでから決める。
CI（`.github/workflows/ci.yml`）が走るので、**落ちたら直してから声をかける**。
