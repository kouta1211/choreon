---
description: 今日の開発セッションを振り返り、得られた知見や教訓を学習ログに自動蓄積する
---

一日の開発の終わりに、以下のステップを自律的に実行してください。

1. **セッションの分析:** 今日の会話履歴や直近のGit差分、解決したエラー内容をスキャンする。
2. **知見の抽出と記録:** 今後の開発に活かせる教訓（技術的なハマりポイント、プロジェクト特有の仕様変更、私の好みのコードの書き方など）を抽出し、`docs/lessons_learned.md` に箇条書きで追記する（許可不要でファイルに書き込むこと）。
3. **次回への引き継ぎ:** 「本日の学びを lessons_learned.md に記録しました。次回の開発は、〇〇の作業から始めるとスムーズです。お疲れ様でした！」と、次回の自分に向けた簡潔なメモを出力してセッションを終了する。

---

## 補足（1 の調べ方）

会話が残っていない状態から呼ばれることもある。そのときは:

```bash
git log --since="16 hours ago" --format='%h %s' --date=short
git diff --stat "HEAD@{16 hours ago}" HEAD 2>/dev/null || git diff --stat HEAD~5 HEAD
git status --short
```

コミットメッセージと差分から辿る。**分からないものを埋めない。**

## 補足（2 の書き方）

- **「起きたこと」ではなく「次はどうするか」を書く。**
  症状の記録は git log にある。ここに要るのは判断の指針
- 1件は3行まで。何が起きた → なぜ → 次はどうする
- 関連するファイル名かコミットの短縮ハッシュを添える
- **同じ教訓が2回目なら、箇条書きを増やさず `.claude/rules/` の該当ファイルへ
  昇格させる。** lessons_learned は流れていく記録、rules は固定するもの

**静かな日は何も書かない。** 教訓が無い日に無理やり1件ひねり出すと、
次から読まれなくなる。「今日は記録することがありませんでした」でよい。

## 補足（3 の引き継ぎ）

次回が別のセッションになるなら、**出力するだけでは消える**。
再開地点（どこまで push したか・次の一手の候補・やらないと決めたこと）は
記憶ファイルの方も更新しておく。

あわせて、コミットしていない変更が残っていないかを見て、
残っていればその事実を引き継ぎに書く（勝手にコミットしない）。
