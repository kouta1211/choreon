# テストと、出す前の確認

## 1. 出す前に必ず通すもの

```bash
npm run verify     # check:docs → lint → test:run → build
```

途中で落ちたら、**そこで止めて直す**。落ちたまま次へ進まない。
テストだけ回すなら `npx vitest run <パス>` で範囲を絞る（全部で700件以上あり、
毎回まわすと遅い）。

**`check:docs` は、ドキュメントが実在するものだけを指しているかを見る**
（`scripts/check-docs.mjs`）。リンク・パス・識別子・手順書の bash に混ざった罠
（`npm run test` は watch で終わらない、`grep -c` は0件で exit 1）。
**文章は lint もテストも見てくれないので、ここで止める。**

**誰も読んでいない文言が残っていないか**もここで見る。機能を消したとき、
文言だけが3言語ぶん残る。**型は3つそろっていることしか見ない**ので、
そろったまま誰にも読まれない（2026-08-21 に4件見つかった）。

動作確認の台本（`docs/qa-checklist.html`）の**同じ項目にキーが2つ無いか**も
ここで見る。項目は JS のオブジェクトなので、`ng` を2つ書くと**後ろが勝って、
前の1行は誰にも読まれないまま消える**。壊れて見えないので気づけない
（2026-08-21 に3件見つかった）。
例示で実在しないものを書くときは、スクリプトの `PLACEHOLDER` へ理由つきで足す。

`lint` が見ているものの中で、**このリポジトリで足したもの**が2つある。

- **`no-floating-promises`**（`src/` の本番コードのみ・型情報を使うので約15秒）
  … `await` の付け忘れを捕まえる。編集はどれも
  【楽観的に画面を変える → 保存する → 失敗したら戻す】で保存は非同期なので、
  await を落とすと**画面だけ変わって保存されず、エラーも誰にも届かない**。
  目に見えない壊れ方なので、人のレビューでは落ちる。
  **意図して投げっぱなしにするものは `void` を付ける**
  （自分でエラーを処理しているもの・アニメーションの完了待ちなど）

- **`no-restricted-syntax`**（`src/**/*.tsx`。テストと `features/i18n/` は対象外）
  … **JSX に直に書いた日本語**を捕まえる。文言は3つそろえる決まりで、
  型がそこを見張っている。**だが直書きはその検査をすり抜ける** —
  英語・韓国語で開いた人にだけ日本語が出る、という壊れ方をする。
  日本語で見ている限り、画面を見ても気づけない。
  拾うのは JSX のテキスト・式の中の文字列とテンプレート・
  `aria-label` などの4つの形。直し方は
  `src/features/i18n/messages/` の ja / en / ko へそろえて足し、`useT()` から読む。

  **同じルールで、角丸の一点物も塞いである**
  （`rounded-[calc(var(--radius)*…)]`）。理由は
  [frontend.md](frontend.md) の2節・6項

## 2. テストはコードの隣に置く

`Foo.tsx` の隣に `Foo.test.tsx`、`marquee.ts` の隣に `marquee.test.ts`。
別のディレクトリへ集めない。

**厚く書くのは `features/*/lib/` の純粋関数。** DOM にも Supabase にも
依存しない計算がここに集めてあり、**壊れても画面のどこが崩れるか見えにくい**。
座標・時間・並び替えの計算は、境目（0・最大値・ひっくり返した向き）まで書く。

コンポーネントのテストは「押したら何が起きるか」だけを見る。
内部の状態を覗きに行かない。

## 3. テストの無いコード変更は原則しない

直す前に、**その挙動を確かめるテストがあるか**を見る。無ければ足してから直す。
特に `features/*/lib/`。例外は、テストの書きようが無いもの
（見た目だけの調整・文言）。

例外処理とバリデーションも**最初から書く**。「後で足す」は残らない。

## 4. テストに歯があるか確かめる

直したバグのテストを足したら、**直した側を一時的に戻して、テストが落ちることを
確かめる**。落ちなければ、そのテストは何も守っていない。

⚠️ **壊せたことを確かめてから、落ちるかを見る**（2026-08-22 に昇格）。
複数行を狙った置換は**黙って当たらない**ことがある。
当たっていない状態でテストを回すと**緑になる**ので、
「歯が無い」と読み違える。順番はこう:

```bash
grep -c "<仕込んだ目印>" <ファイル> || true   # 0 なら、まだ何も壊していない
npx vitest run <テスト>               # ここで初めて落ちるかを見る
```

置換そのものも、ワンライナーではなく**ファイルに書いたスクリプト**で
行う（2026-08-21 に正規表現が消えた件と同じ理由）。

⚠️ **`.gitattributes` の `eol=lf` は、作業ツリーを直さない**（2026-09-15 に
訂正）。ここには以前「LF に固定してある」と書いていたが、あれが効くのは
**リポジトリに入る側**と、それ以降に取り出した分だけ。**既に手元にある
ファイルは CRLF のまま残る**（2026-09-15 時点で 41ファイル。`ja.ts` や
`qa-checklist.html` がそう）。`git diff` は「次に Git が触るとき LF に
置き換わる」と警告するだけで、いまは直らない。

だから、**置換スクリプトはファイルの改行を読んでから当てる**。

```python
src = io.open(path, encoding="utf-8", newline="").read()   # 改行を潰さずに読む
eol = "\r\n" if "\r\n" in src else "\n"                    # ファイルに合わせる
anchor = ANCHOR.replace("\n", eol)                         # 差し込む文も同じ
if src.count(anchor) != 1:
    sys.exit("当たらなかった")                              # 門番。黙って進ませない
```

**それでも上の確認はやめない** — 当たらない理由は改行だけではない
（空白・全角・書き換わった直後の行）。

### 純粋関数のテストは、**そこへ何を渡すか**を守っていない

**2026-08-24 に1日で3回出たので、ここへ上げた。**

判断を `features/*/lib/` の純粋関数へ出して、境目までテストを書く。
そこまでは正しい。**穴はその外側にある** — 呼び出し側が
【正しい引数を渡しているか】と【返り値を正しい所へ出しているか】は、
純粋関数のテストからは見えない。

その日に出た3件は、どれもこの形だった。

| 壊した所 | 純粋関数のテスト | 実際に落ちたか |
| --- | --- | --- |
| `isAnyDragging: active !== null` | `groupDragFollow` にある | **323件すべて緑** |
| 消したあとの行き先の呼び出し | `sceneAfterDelete` にある | **22件すべて緑** |
| 区間へ渡す移動時間 | `segmentSplit` にある | **28件すべて緑** |

1件目は、**その配線が原因の不具合を2日前に実機で踏んでいた**。
それでも歯は無かった。

**だから、割ったあとの歯の確認は【移した先】を潰すまでやる。**
「割る前が緑だった」は「その行が守られていた」ではない。

```bash
# 純粋関数の側だけでなく、**呼び出し側が渡す値**を潰してみる
#   例: splitSegment(span, scene.moveSeconds) → splitSegment(span, null)
# ここで何も落ちなければ、そこに網は無い
```

落ちる相手が居なければ、その場で足す。**呼び出し側のテストは、
純粋関数と答えが分かれる場合で書く** — 3件目は「真ん中を消したときだけ
先頭へ飛ぶかどうかが分かれる」ところで縛った。同じ答えになる例で書くと、
潰しても緑のままになる。

## 5. 画面に見える変更をしたら、動作確認の台本を更新する

user は**実機で自分の目で**確かめる。その台本が `docs/qa-checklist.html`。
手順は `.claude/skills/qa-checklist/SKILL.md`（`/qa-checklist` で呼べる）。

- 足した / 挙動を変えた / 消した / バグを直した → **コミット前に更新する**
- 内部の整理・型・テストだけなら更新しない

**このファイルは 188KB ある。全部読まない。** `grep -n` で該当の章を探して、
その周りだけ `sed -n` で開く。

## 6. 実機で見るとき

`npm run dev` は user が既に立てていることが多い。**ポート3000が塞がっていたら
新しく立てず、そのサーバーを使う。**

⚠️ **その dev サーバーが、変更を拾わなくなることがある**（2026-08-20 に2回）。
症状は「直したのに画面が変わらない」で、**スーパーリロードでも直らない**
（サーバー側が古いものを返しているので、ブラウザは無実）。

見分け方 — **配信されている中身を見る**。ブラウザではなく `curl` で:

```bash
curl -s http://localhost:3000/login | grep -o '/_next/static/[^"]*\.css' | head -1
```

出たパスをもう一度引いて、直した値が入っているかを見る（JS なら
`/_next/static/chunks/...js` を同じ手順で）。入っていなければサーバーが古い。

直し方は**立て直す**。ポートを掴んだままのことがあるので、
`taskkill /PID <pid> /F` で落としてから起動する。

**画面を確かめる前に、必ずこの確認を通す。** 通さずに「直した」と伝えると、
user が古い画面を見て「変わっていない」と報告することになり、一往復増える。

本番は https://choreon.vercel.app 。素の「Internal Server Error」は環境変数の
未設定、SSO へ飛ばされたらデプロイ保護が掛かっている。
