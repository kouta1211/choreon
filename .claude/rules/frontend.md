# 画面まわりの規約（Next.js 16 / React 19 / Tailwind 4）

## 0. Next.js は訓練データと違う

`AGENTS.md` のとおり、入っている Next は 16 系で**破壊的変更が入っている**。
`next/*` の API に触る前に `node_modules/next/dist/docs/` の該当ガイドを読む。
記憶で書かない。

## 1. コンポーネントをどこに置くか

判断基準は**「Zustand のストアに触るか」**。見た目の複雑さでは決めない。
表と例は `src/components/README.md` にある。要約だけ:

```
atoms      ストアに触らない。propsだけで完結
molecules  ストアに触らない。atoms を組み立てる
organisms  ストアを読む・書く / Supabase を呼ぶ
templates  organisms の配置だけ。2ページ以上が同じ配置を使うときだけ作る
ui/        shadcn 由来の汎用パーツ。色や余白は必ずトークン経由で当てる
```

**依存は下向きだけ。** molecules がストアを読み始めたら organisms へ移す合図。

## 2. 色・余白・角丸は必ずトークン

テーマが10種あり、**CSS 変数の差し替えだけで全部切り替わる**（`src/app/themes.css`）。
生の色や `rounded-[12px]` を書くと、その1箇所だけテーマに追従しなくなる。

- 色 … `text-fg-strong` `bg-surface` `text-fg-muted` のようなトークン名
- 余白 … `px-gutter` `py-unit`
- 角丸 … `rounded-xl` など Tailwind の段階。`rounded-[...]` は使わない

新しい値が要るなら、まずトークンを足すことを検討する。

**一度壊すと気づきにくいものが6つある。** どれも見た目は動いて見えるのに、
テーマを切り替えた瞬間や特定の画面だけで破綻する。

1. **`DANCER_COLOR_PALETTE` を CSS 変数にしない。** これは Supabase に保存され、
   色チップの選択状態の照合にも使う**実データ**。`var(--dancer-N)` を書き込むと
   壊れる。テーマごとの色替えは、描画時に `themedDancerColor()` で変換する
2. **`themes.css` は記述順で勝たせている。** 既定値は `:root, [data-theme]` に置き、
   各テーマはその下に `[data-theme="..."]` で並べる。`:root[data-theme=...]` に
   戻すと一覧シートのミニチュアが効かなくなる。**CSS 変数は親から継承する**ので、
   ミニチュアのために既定値は `[data-theme]` にも当たっていなければならない
3. **同じトークンでも、テーマによって半透明だったり不透明だったりする。**
   `--surface-*` は暗い系が `rgba(255,255,255,0.0x)` の重ね、紙・黒板系は
   不透明な色そのもの。**半透明の側では、地に敷いた質感（方眼・グレイン・
   幕）が透けて、上に載せた文字が沈む**（2026-08-20 に2回: 吹き出しと
   ホームのカード）。
   - 地の上に**浮く**もの（板・吹き出し・トースト） → `.overlay-panel`
   - 並べて**読む**面（カード・パネル） → `.card-surface`
     （地の色を敷いてから面の色を重ねるので、必ず不透明になる）
   - 窪んで見せたい面（シーンのコマ） → `.card-surface-sunken`
     （同じ形で段だけ違う。2026-08-22 に追加）
   - 押せるカードだけ `.card-surface-interactive` を足す（手応えは
     押せるものにしか付けない）

   **3度目が出た**（2026-08-22。左のシーン一覧が `bg-surface/60`、
   シーンのコマが `bg-surface-sunken`）。生のトークンを面に当てると、
   **暗いテーマでだけ消える**。並べて読む面に `bg-surface*` を直に書かない。

   **ここに lint は置いていない。** 半透明の `bg-surface*` は、浮くボタン・
   sticky の帯・hover の下地では**意図して**使っている（10箇所）。
   機械には「並べて読む面か、上に浮く小物か」が見分けられず、塞ぐと
   偽陽性の方が多くなる。**見分けるのは人の側**で、判断はこの3項が持つ。
4. **色の直書きを増やさない。** `git grep -n "zinc-\|pink-\|slate-" -- src` が
   増えていたら直す。意味を運ぶ色（顔被りの赤など）だけは例外で、その旨の
   コメントが要る
5. **シートの中身の左右の余白は `px-gutter` に揃える**（2026-08-20）。
   以前は 12 / 14 / 16 / 18px の4通りに分かれていて、板を開くたびに
   文字の始まる位置が変わっていた。段を分けたいときは上下で取る
6. **角丸は `--radius` からの比。** `rounded-lg` のような名前をそのまま使い、
   `rounded-[12px]` を足さない（`rounded-full` は円なので対象外）。
   **段の間の刻みを増やさない**（2026-08-20）。`*0.6` `*0.8` `*0.9` のような
   一点物が16種類まで増えて、同じ板の中で角の丸みが3通りになっていた。
   名前のある段（sm / md / lg / xl / 2xl / 3xl）のどれかへ寄せる。
   **2026-08-21 に残り24箇所を寄せ、ESLint で塞いだ**ので、
   `rounded-[calc(var(--radius)*…)]` はもう書けない。
   枠の内側の面（`rounded-[max(0px,calc(var(--radius)-2px))]`）は別の形で、
   これは当たらない（外の角丸から枠の太さを引くという幾何の話）。
   **固定値がどうしても要るなら、その場に理由をコメントで書く**（例:
   囲んで選ぶ枠は、角を大きく取るテーマで「カード」に見えてしまうため
   3px 固定）

## 3. ステージの座標系

**Y が大きいほど客席側（手前）。1ユニット = 約 90cm。**
ここを取り違えた変更は**テストが通っても意味が反転する**（左右は合っているのに
前後だけ逆、という壊れ方をする）。画面へ描くときは「客席を上にする」設定で
上下がひっくり返るので、必ず `features/canvas/lib/stageFlip.ts` の `toScreenY`
を通す。詳しくは [../../docs/features/canvas.md](../../docs/features/canvas.md)。

## 4. 文言は3言語そろえて足す

`src/features/i18n/messages/` に `ja.ts` / `en.ts` / `ko.ts` があり、
**型で3つそろっていることを強制している**。1つでも欠けるとビルドが落ちる。
画面に出す文字列を直書きしない。読むのは `useT()`（`LocaleProvider`）、
サーバー側は `src/features/i18n/server.ts`。

## 5. 作る画面は PC 前提（2026-08-18 の方針転換）

README「フェーズ6」で、**作る側＝PC / タブレットのブラウザ、見る側＝スマホ**に
割った。だから:

- キャンバス・タイムラインなど**作成画面は PC のレイアウトと操作性で作る**
- スマホ幅向けの無理な折りたたみや、複雑なタッチ制御は**足さない**
- 修飾キー（Shift / Ctrl / ⌘）や右クリックを前提にした操作を**足してよい**
- **狭い幅では、作る側の画面をどれも使わせない**（2026-08-20）。
  案内は `NarrowScreenGate` が **layout で1回だけ**描く。出さないのは
  `/view` だけ。作成画面にだけ置くと、ホームや設定は狭い幅でも触れてしまう
- **この案内は入口の案内であって、鍵ではない。** 幅で出し分けているだけ
  なので、窓を広げれば誰でも通れる。**守っているのは Supabase 側**
  （RLS と GRANT）。ここを鍵だと思って、あちらの守りを緩めない
  `NarrowScreenNotice` に逃げ道は無い。以前は「このまま開く（非推奨）」を
  残していたが、**入れても操作できない画面へ通していただけ**だった。
  板に出す出口は、共有済みのときのビューアへのリンクだけ
- **板の文は【端末】ではなく【幅】で書く。** 出し分けは幅（768px）なので、
  PC でウィンドウを狭めても出る。「スマホでは使えません」と書くと、
  その人には嘘になる
- 閲覧側（`/view`）はスマホが主戦場。ここでタッチを削らない

## 6. 画面幅で分けるときは CSS でやる

`useScreenKind` はサーバーでは `"phone"` を返す。これで JSX を出し分けると
**初回描画が一瞬スマホ用になってから切り替わる**（ちらつく）。
`min-[768px]:hidden` のように **CSS のブレークポイントで消す**。

## 7. 新しく作る前に、既にある部品を探す

`src/components/atoms` と `molecules` に、汎用のものはだいたい揃っている
（`PressableButton` `BottomSheet` `SegmentedControl` `Tooltip` など）。
同じ見た目を2つ作ると、テーマを直すときに片方が取り残される。
